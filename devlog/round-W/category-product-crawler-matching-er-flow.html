WalletSavior 카테고리·상품·크롤러·매칭 ER 및 데이터 흐름

발표용 요약 문서입니다. 이 프로젝트는 “마트 4사에서 같은 생활 식품군을 묶고, 어디가 가장 싼지와 지난 가격 대비 현재가를 보여주는 서비스”입니다. 핵심은 크롤러가 가져온 각 마트의 다른 상품명·카테고리를 통합 카테고리와 매칭 규칙으로 정리하는 것입니다.

현재 DB raw categories: 1,932개
현재 DB unified categories: 228개
현재 DB products: 6,527개
unified 연결 상품: 5,174개
leaf 연결 상품: 4,482개
product match rules: 4,781개

1. 발표에서 말할 핵심 문제

현재 문제

raw 카테고리가 너무 많고, 각 마트가 쓰는 이름이 서로 다릅니다. 예: 정육ㆍ계란, 계란15구, 등급란ㆍ차별화란.

이 상태로는 “돼지 앞다리 100g은 어느 마트가 싼가?” 같은 비교가 어렵습니다.

잘못된 화면 예

정육/계란 같은 너무 큰 묶음 안에 계란, 곰탕, 돼지고기가 함께 나오면 평균가가 의미 없어집니다.

평균가는 계란, 돼지 앞다리, 소 안심 같은 세부 상품군에서 계산되어야 합니다.

목표

마트별 상품명을 그대로 비교하지 않고, 통합 카테고리 leaf와 매칭 규칙으로 묶습니다.

예: 보먹돼 앞다리, 탄탄포크 앞다리, 국내산 돼지 앞다리 → 정육 > 돼지고기 > 앞다리.

3. 데이터 흐름

1

크롤러 수집

이마트·홈플러스·롯데마트·코스트코에서 상품명, 가격, 이미지, canonical URL, 마트 원본 카테고리를 수집합니다.

2

Pending 적재

수집 결과는 바로 상품 DB에 쓰지 않고 pending_ingestions에 저장해 검수/승인 가능한 상태로 둡니다.

3

카테고리 매핑

마트 원본 카테고리 경로를 mart_category_mappings로 통합 카테고리 leaf에 연결합니다.

4

상품 매칭

이전에 분류한 상품명은 product_match_rules로 자동 연결합니다. 미매칭만 외부 AI/관리자 검수로 보냅니다.

5

웹 비교

웹은 raw 카테고리가 아니라 unified leaf 기준으로 4사 가격, 평균가, 주차별 가격 이력을 보여줍니다.

4. 현재 DB 상태 요약

product_match_rules4,781이름/정규화 제목 기반 자동분류 규칙. 신규 크롤 상품 재분류에 사용.
matching_entries0brand|name_core|pack 기반 구상 테이블은 현재 운영 흐름에서 거의 쓰이지 않음.

5. 현재 상위 분포: raw vs unified

구분 많이 붙은 카테고리 예시 해석
raw Category 과일 116, 대파 102, 간편식ㆍ밀키트 94, 생수ㆍ음료 94, 라면 87 마트별/라운드별 이름이 섞인 원본 분류입니다. 웹 최종 비교 기준으로 쓰면 카테고리가 흩어집니다.
UnifiedCategory 소스/양념 432, 밀키트/간편조리 412, 라면 411, 과자/쿠키 344, 생수 286, 흰우유 106, 돼지 앞다리 15 실제 비교에 더 가까운 leaf입니다. 현재 5,174개 상품이 통합 카테고리에 연결됐고, 4,482개는 leaf까지 내려갔습니다.
개선 결과 정육/계란 root는 계란/알류·닭고기·소고기·돼지고기 하위 카드만 표시, 돼지 앞다리 leaf에서 실제 상품 15개 비교 root 평균을 제거하고 leaf에서만 평균/최저가를 보여주도록 API와 화면을 조정했습니다.

7. 앞으로 DB를 고치는 작업 순서

순서 작업 결과물
1 현재 walletguardian.db를 별도 작업 DB로 복사 실서비스 DB를 망가뜨리지 않고 분류 실험 가능
2 현재 raw category/product/source path를 export 상품명, 마트, 원본 카테고리, 가격, 단위가 들어간 분류 입력 파일
3 식품 기준 통합 leaf tree 재작성 돼지 앞다리, 계란 30구, 흰우유, 두부, 감귤 등 비교 가능한 leaf
4 상품별 unified_category_id 업데이트 6,527개 상품 중 식품 상품을 최대한 leaf에 연결
5 마트 원본 카테고리 매핑 추가 다음 크롤링부터 source category만으로도 자동 leaf 분류
6 상품명 기반 match rule 추가 같은 상품 재수집 시 자동으로 같은 category/canonical product에 연결
7 웹에서 root → 중분류 → leaf → 4사 비교 검증 “돼지 앞다리 4사 중 어디가 싼가”를 실제 화면에서 확인

8. 발표 한 문장 요약

핵심 메시지

WalletSavior는 마트 사이트별로 흩어진 상품명과 카테고리를 그대로 보여주는 서비스가 아니라, 크롤러 원본 데이터 → 통합 카테고리 → 상품 매칭 규칙 → 가격 이력으로 이어지는 파이프라인을 통해 “같은 생활 식품군의 현재 최저가와 과거 가격 대비 싼 정도”를 보여주는 플랫폼입니다.

주의: 이 문서는 현재 DB와 코드 기준의 발표용 요약입니다. 실제 라이브 품질을 위해서는 아직 6,527개 상품 중 미분류 상품을 leaf 카테고리로 재배치하고, 4사 비교 가능한 상품군을 우선 구축해야 합니다.
