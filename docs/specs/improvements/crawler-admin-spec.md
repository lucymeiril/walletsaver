# 크롤러 관리자 종합 개선 기획서

## 1. 처리 완료 항목 정리

### 1.1 문제점
- 승인/거부 처리 끝난 항목이 목록에 계속 남아있음
- 시간이 지나면 수백 개 쌓여서 관리 불가
- 개별 삭제만 가능, 일괄 정리 없음

### 1.2 개선 사항

#### A. 자동 정리 시스템
```
설정: [처리 완료 항목 자동 삭제] [토글 ON/OFF]
      완료 후 [7일 ▼] 경과 시 자동 삭제
      [승인 완료만 ▼] 삭제 | [승인+거부 모두] 삭제
```

#### B. 수동 정리 버튼
```
상단 필터 바:
[대기중] [1차승인] [승인] [거부]  ···  [처리 완료 정리 🗑️]
```
- "처리 완료 정리" 클릭 → 확인 모달
- "승인 완료 47건, 거부 12건을 삭제합니다"
- 옵션: [승인만 삭제] [거부만 삭제] [전부 삭제]

#### C. 백엔드 API
```
POST /api/ingestions/cleanup
{
  "status": ["approved", "rejected"],  // 또는 ["approved"]
  "older_than_days": 7,  // 선택적
  "confirm": true
}
→ { "deleted": 59, "remaining": 23 }
```

## 2. 품질 점수 재설계

### 2.1 문제점
현재 공식: `score = 1.0 - (missing * 0.4) - (outlier * 0.3) - (dup * 0.3)`
- 무엇이 부족한지 직관적이지 않음
- 모든 필드를 동일하게 취급 (이름 없는 것 vs 이미지 없는 것 가중치 동일)
- 점수만 보고는 승인/거부 판단 불가

### 2.2 개선된 품질 시스템

#### A. 핵심 필드 가중치 차등
```python
FIELD_WEIGHTS = {
    "name": 1.0,        # 상품명 — 필수 (없으면 품질 0)
    "price": 0.9,       # 가격 — 거의 필수
    "original_price": 0.5,  # 원래가 — 있으면 좋음
    "category": 0.4,    # 카테고리 — 자동분류로 보완 가능
    "image_url": 0.3,   # 이미지 — 있으면 좋음
    "unit": 0.3,        # 단위 — 있으면 좋음
    "valid_from": 0.2,  # 할인 시작일
    "valid_to": 0.2,    # 할인 종료일
}
```

#### B. 시각적 품질 표시
```
품질 점수 대신 → 시각적 체크리스트:

✅ 상품명    ✅ 가격    ⚠️ 원래가 없음    
✅ 카테고리(자동)  ❌ 이미지  ✅ 단위    
⚠️ 할인기간 불명

종합: 양호 (7/9 항목 충족)
자동분류: livestock.pork.belly (신뢰도 92%)
```

#### C. 승인 추천 시스템
```
점수 기반 자동 추천:
- 🟢 승인 추천 (핵심 필드 모두 충족, 이상치 없음)
- 🟡 검토 필요 (일부 필드 누락 또는 가격 의심)
- 🔴 거부 추천 (상품명/가격 누락, 심각한 이상치)
```

#### D. 일괄 자동 승인
```
[🟢 항목 일괄 승인] → 승인 추천인 항목 모두 자동 승인
```

## 3. 날짜/신선도 시스템

### 3.1 문제점
- 크롤링 날짜가 눈에 안 띔
- 할인 기간(valid_from~valid_to) 표시 없음
- 데이터 신선도 판단 불가

### 3.2 개선 사항

#### A. 상대 시간 + 신선도 배지
```
데이터 카드:
┌─────────────────────────────────────────┐
│ 🛒 이마트 크롤링 #127                    │
│ 상품 44개 | 🟢 2시간 전                   │
│ 할인기간: 4/1(화) ~ 4/7(월) | D-4       │
│                                         │
│ 품질: ████████░░ 82%                    │
│ [상세보기] [승인] [거부]                  │
└─────────────────────────────────────────┘
```

**신선도 색상:**
- 🟢 초록: 24시간 이내
- 🟡 노랑: 24시간~72시간
- 🟠 주황: 72시간~7일
- 🔴 빨강: 7일 초과 (데이터 신뢰도 낮음)

#### B. 할인 기간 디데이
- "D-4" (4일 남음), "D-Day" (오늘 마감), "만료 +2일" (2일 지남)
- 만료된 항목: 회색 처리 + ~~취소선~~
- 필터: [진행중만] [만료 포함] [만료만]

#### C. 타임라인 뷰
```
4/3 ──●── 이마트 44개 (승인)
4/2 ──●── 홈플러스 38개 (대기)
4/1 ──●── 롯데마트 52개 (거부)
      ●── 무신사 120개 (승인)
3/31──●── 이마트 41개 (승인)
```

## 5. 만료 할인 처리

### 5.1 자동 감지
- 매 시간 또는 크롤링 시 → `valid_to < now()` 체크
- 만료된 항목 → 자동 마킹 (is_expired = true)
- 관리자에게 알림: "만료된 할인 23건 발견"

### 5.2 처리 옵션
```
[만료 항목 처리]
○ 아카이브로 이동 (통계 보존)
○ 비활성화 (웹에서 숨김, DB 보존)
○ 삭제 (완전 제거)
[일괄 처리] [개별 선택]
```

## 7. 테스트 시나리오

1. 처리 완료 정리 → 승인 완료 항목 삭제 → 목록 갱신
2. 자동 정리 설정 (7일) → 7일 지난 항목 자동 삭제
3. 품질 체크리스트 표시 → 핵심 필드별 상태 확인
4. 승인 추천 🟢 항목 → 일괄 자동 승인 → DB 반영
5. 신선도 배지 → 24시간 이내 🟢, 7일 초과 🔴
6. 할인 만료 D-Day → 만료 마킹 → 아카이브 이동
7. 크롤러 성과 → 주간 추이 차트 → 실패 크롤러 식별
8. 타임라인 뷰 → 날짜별 크롤링 이력 확인
