# 지갑 지키미 — 웹사이트 기획서

## 기획팀 토론 결과

### 기획자 구성
- **기획자A (UX 전문가)**: 초보자도 3초 안에 정보 도달, 직관적 UI
- **기획자B (핫딜 고인물)**: 상세 비교, 필터링, 데이터 깊이
- **기획자C (일반 소비자)**: "귀찮아서 안 찾아보는" 사람도 쓰게

## 1. 홈페이지

### 사용자 목표
"이 사이트가 뭔지 3초 만에 이해하고, 내가 원하는 정보로 바로 이동"

### 현재 문제점
- 각 섹션마다 별도 API 호출 → 초기 로딩 느림
- 장보기/관심상품이 로컬 상태만 (서버 동기화 없음)
- 위치 기반 서비스가 고정 좌표 사용 (실제 GPS 미연동)
- 마트 전단 미리보기 데이터 구조 불일치

### 개선 방안

[기획자A]: 홈은 "오늘의 핫딜" 하나만 크게 보여주고 나머지는 카드로 나열하자. 정보가 너무 많으면 초보자가 압도당한다.
[기획자B]: 고인물은 홈 안 거친다. 하지만 "오늘의 최저가 TOP 5"는 있어야 한다. 어제 대비 가격 변동도.
[기획자C]: 나는 "지금 뭐가 싸?" 하나만 알고 싶다. 카테고리 버튼 6개도 많다. 3개면 충분.
→ 합의: 상단에 "오늘의 핫딜 TOP 3" 대형 카드, 아래에 카테고리 퀵링크 (식품/생활/패션), 그 아래 각 섹션 미리보기

### 필수 기능
- P0: GPS 위치 연동 (navigator.geolocation)
- P0: API 병렬 호출 최적화 (Promise.allSettled)
- P0: 오늘의 핫딜 TOP 3 (할인율 기준)
- P1: 장보기 리스트 서버 동기화
- P1: 개인화 추천 (최근 검색 기반)
- P2: 푸시 알림 (가격 알림)

### 사용자 시나리오
> 퇴근길 직장인이 "오늘 저녁 뭐 먹지?" → 홈에서 "동네 물가" 클릭 → 현재 위치 기반 주변 식당 → 가격 비교 → 결정

## 2. 핫딜 페이지

### 사용자 목표
"지금 가장 핫한 딜을 빠르게 찾고, 진짜 핫딜인지 확인하고, 바로 구매"

### 현재 문제점
- 댓글/투표가 로컬 상태만 → 새로고침하면 초기화
- 가격 히스토리가 DB에 없으면 빈 차트
- 출처별 필터는 있으나 신뢰도 표시 없음

### 개선 방안

[기획자A]: 핫딜 카드에 "커뮤니티 평가" 배지를 붙이자. 🔥 10명 이상 핫딜 투표 → 검증됨 표시
[기획자B]: 가격 히스토리 차트가 핵심이다. 없으면 "데이터 수집 중" 표시하고, 유사 상품 가격이라도 보여줘야 한다.
[기획자C]: 나는 "가장 많이 할인된 것"만 보고 싶다. 기본 정렬이 할인율 내림차순이어야 한다.
→ 합의: 기본 정렬 = 할인율 내림차순, 커뮤니티 검증 배지, 가격 데이터 없으면 유사 상품 제안

### 필수 기능
- P0: 댓글/투표 서버 저장 (DB 연동)
- P0: 외부 링크 (원본 사이트로 이동) 확실한 CTA 버튼
- P0: 실시간 핫딜 알림 표시 (새 핫딜 N개)
- P1: 커뮤니티 검증 배지 (투표 수 기반)
- P1: 유사 상품 가격 비교 제안
- P2: 핫딜 만료 카운트다운

## 3. 가격 비교 페이지

### 사용자 목표
"이 상품이 지금 사도 괜찮은 가격인지, 더 기다려야 하는지 판단"

### 현재 문제점
- 속성 변형(Variants) 데이터가 DB에 없어서 빈 배열
- 통계가 계산 기반 → 실제 수집 데이터와 불일치
- 관련 핫딜이 고정 필터 (category=food)

### 개선 방안

[기획자A]: "지금 사도 괜찮아요" 한 줄이면 충분한 사람도 있다. 상세 분석은 접기로 숨기자.
[기획자B]: 30일/90일/365일 가격 추이는 필수. 마트별 바 차트도 좋은데 "어디서 사야 가장 싸?" 결론을 내줘야 한다.
[기획자C]: 그래프 보기 싫다. "삼겹살 100g 3,500원 — 지금이 적기! 이마트가 제일 싸요" 이 한 줄이면 된다.
→ 합의: 상단에 결론형 요약 (한 줄), 중간에 시각적 가격 바, 하단에 접을 수 있는 상세 분석

### 필수 기능
- P0: 결론형 요약 ("어디서 사면 가장 싸고, 지금이 적기인지")
- P0: 마트별 최저가 비교 실제 데이터 연동
- P0: 가격 추이 차트 실데이터
- P1: 상품 검색 자동완성 (DB 키워드 연동)
- P1: 관련 핫딜 동적 연결 (같은 카테고리)
- P2: 가격 알림 설정 ("이 가격 이하면 알림")

## 4. 마트 할인 페이지

### 사용자 목표
"이번 주 마트에서 뭐가 세일하는지 한눈에 보고, 어디가 제일 싼지 비교"

### 현재 문제점
- 데이터 구조 불일치 (API 응답 형식 차이)
- 비교 모드 정규화 부정확
- 전단지 PDF 미지원

### 개선 방안

[기획자A]: 마트 3곳 동시 비교가 핵심이다. 탭으로 하나씩 보는 건 비효율. 공통 상품을 한 테이블에 나란히 보여주자.
[기획자B]: 전단지 이미지 + 텍스트 데이터 모두 제공. 이미지로 전체 보고, 텍스트로 상세 비교.
[기획자C]: "이번 주 장볼 거 → 어느 마트가 제일 싸?" 자동 계산 기능이 있으면 최고.
→ 합의: 기본은 3사 비교 테이블, 개별 마트 상세는 탭, 전단지는 이미지 뷰어, 장보기 최적화 계산기

### 필수 기능
- P0: 3사 동시 비교 테이블 (공통 상품)
- P0: 마트별 프로모션 실데이터 (크롤러 연동)
- P0: SSG/홈플러스몰/롯데온 외부 링크
- P1: 전단지 이미지 뷰어 (확대/축소)
- P1: 장보기 리스트와 연동 ("내 장보기 리스트 기준 최저 마트")
- P2: 과거 전단지 아카이브

## 5. 동네 물가 (지도) 페이지

### 사용자 목표
"내 주변에 뭐가 있고, 어디가 가장 싸거나 가성비 좋은지 한눈에"

### 현재 문제점
- GPS 미지원 (고정 좌표)
- Naver API 의존성 + Playwright 브라우저 풀 필요
- 메뉴 가격 파싱 부정확
- 전화/네비게이션 UI만 있고 기능 없음
- 레시피 5개 고정 → 확장 불가
- iframe 역방향 동기화 불가 (cross-origin)

### 개선 방안

[기획자A]: 위치 → 범위 → 카테고리 트리 순서로 탐색. 버튼 누를 때마다 범위가 좁아지는 드릴다운 방식.
[기획자B]: 주유소는 가격 정렬이 핵심. 휘발유/경유 동시 표시. 셀프/24시간 필터.
[기획자C]: "오리역 근처 중식당" 검색하면 끝이어야 한다. 카테고리 눌러가는 건 귀찮다.
→ 합의: 검색과 카테고리 드릴다운 두 가지 경로 모두 제공. 검색이 기본, 카테고리는 "뭐 먹을지 모르는" 사용자용

### 필수 기능
- P0: GPS 위치 연동 (navigator.geolocation + 수동 입력)
- P0: 반경 설정 (1km/3km/5km/10km 드롭다운)
- P0: 카테고리 트리 (대분류 → 소분류 → 업소 목록)
- P0: 주유소 가격 정렬 (휘발유/경유 오름차순)
- P0: 업소 상세 모달 (메뉴, 가격, 지도, 전화)
- P1: iframe ↔ 사이드바 양방향 동기화
- P1: 레시피 계산기 동적 확장
- P2: 즐겨찾기 업소 저장

### 사용자 시나리오
> "성남시 정자역 주변 3km, 뭐 있지?" → 주유소 | 음식 | 카페 | 병원... → 음식 → 중식 | 한식 | 일식... → 중식 → 홍콩반점, 니뽕내뽕... → 모달로 메뉴/가격 확인

## 6. 커뮤니티 페이지

### 사용자 목표
"핫딜 정보 공유하고, 다른 사람 의견 듣고, 진짜인지 검증"

### 현재 문제점
- 이미지 업로드 API 없음
- 게시글 수정/삭제 UI 미노출
- 댓글 로컬 상태만
- 인증 체크 미흡

### 개선 방안

[기획자A]: 핫딜 게시판과 자유 게시판의 차이가 명확해야 한다. 핫딜은 가격/링크 필수, 자유는 자유.
[기획자B]: 핫딜 게시글에 "적정가 대비 O% 할인" 자동 표시. DB 연동으로 가격 검증 자동화.
[기획자C]: 글쓰기가 간편해야 한다. 링크만 붙여넣으면 상품 정보 자동 추출되면 좋겠다.
→ 합의: 핫딜 게시판은 구조화된 양식 (가격/링크 필수 + 자동 검증), 자유 게시판은 자유 형식

### 필수 기능
- P0: 댓글 서버 저장 (DB 연동)
- P0: 게시글 수정/삭제 UI
- P0: 이미지 업로드 (파일 서버 또는 Base64)
- P1: 핫딜 가격 자동 검증 (DB 적정가 대비)
- P1: 인기 게시글 상단 고정
- P2: 사용자 프로필/활동 이력

## 7. 쇼핑 페이지

### 현재 상태
- 별도 페이지 미구현 (핫딜 페이지에서 패션 카테고리로 필터)

### 개선 방안
[기획자A]: 별도 페이지 불필요. 핫딜 페이지의 패션 필터로 충분.
[기획자B]: 무신사/유니클로/지오다노 각각 탭으로 분리하고 할인율 정렬이면 된다.
[기획자C]: 동의. 핫딜 페이지에서 "패션" 누르면 되잖아.
→ 합의: 핫딜 페이지 내 패션 필터 강화 (브랜드별 탭, 할인율 정렬)

## 8. 검색 기능

### 사용자 목표
"원하는 것을 최소 타이핑으로 찾기"

### 현재 문제점
- 대부분 직접 fetch() 사용 (API 클라이언트 미사용)
- 자동완성이 DB 키워드와 연동 불완전
- 검색 결과 분류 미흡

### 개선 방안
[기획자A]: 검색창 하나로 모든 것 통합. "삼겹살" 치면 가격 + 핫딜 + 마트 세일 + 주변 고깃집 전부 나와야 한다.
[기획자B]: 카테고리별 탭으로 결과 분류 (상품 | 핫딜 | 커뮤니티 | 동네)
[기획자C]: 자동완성이 빨라야 한다. 2글자만 치면 추천 나와야지.
→ 합의: 통합 검색 + 결과 카테고리 탭 + 2글자 자동완성

### 필수 기능
- P0: 통합 검색 결과 카테고리 분류
- P0: 자동완성 2글자부터 (디바운스 300ms)
- P1: 최근 검색어 + 인기 검색어
- P1: 검색 결과 내 정렬/필터
- P2: 음성 검색

## 공통 개선사항

### UI/UX 원칙
1. **3초 규칙**: 원하는 정보까지 3초 이내 도달
2. **한 줄 결론**: 복잡한 데이터도 결론 한 줄로 요약
3. **점진적 공개**: 초보자는 요약만, 고인물은 상세 분석 열기
4. **반응형**: 모바일 우선 설계

### 기술 공통
- 모든 API 호출을 ApiClient 클래스로 통일
- 에러 상태 한국어 메시지
- 로딩 스켈레톤 (스피너 대신)
- 빈 상태 일러스트 + 안내 메시지
