# 지갑 지키미 — 크롤러 관리자 기획서

## 기획팀 토론 결과

### 기획자 구성
- **기획자A (UX 전문가)**: 모니터링 직관성, 장애 시 빠른 대응 UI
- **기획자B (크롤링 운영자)**: 실제 크롤러 운영 업무, 장애 대응, 데이터 품질
- **기획자C (비즈니스)**: 핫딜 서비스에서 크롤러 데이터의 역할, 안정성

---

## 1. 대시보드

### 운영자 목표
"전체 크롤러 상태를 한눈에 파악하고, 문제가 있으면 즉시 인지"

### 현재 문제점
- 수동 새로고침 버튼 없음 (마운트 시 1회만 호출)
- 차트가 최근 7일 고정, 날짜 범위 선택 불가
- 크롤러별 성능 분석 없음
- WebSocket/폴링 없어 실시간 아님

### 개선 방안

[기획자A]: 대시보드는 "신호등" 역할을 해야 한다. 전체 녹색이면 안심, 하나라도 빨간색이면 즉시 눈에 띄어야 한다.
[기획자B]: 크롤러별 성공률 히트맵이 있으면 좋겠다. 어떤 크롤러가 최근 자주 실패하는지 한눈에.
[기획자C]: 데이터 신선도가 중요. "이마트 데이터가 3일 전 것"이면 서비스 품질이 떨어진다.
→ 합의: 상단에 전체 상태 신호등 + 긴급 알림 배너, 중단에 크롤러별 상태 히트맵, 하단에 데이터 신선도 패널

### 필수 기능
- P0: 수동 새로고침 버튼
- P0: 실패/에러 크롤러 긴급 알림 배너 (빨간색, 상단 고정)
- P0: 크롤러별 상태 카드 (성공/실패/비활성 색상 코딩)
- P1: 데이터 신선도 패널 (각 데이터 소스 마지막 업데이트 시간)
- P1: 날짜 범위 선택 가능한 차트
- P2: 자동 새로고침 (30초 폴링 또는 WebSocket)

### 운영자 시나리오
> 아침 출근 → 대시보드 확인 → "이마트 실패 1회" 빨간 알림 → 클릭 → 로그 확인 → 재실행

## 2. 크롤러 관리

### 운영자 목표
"19개 크롤러를 개별적으로 제어하고, 실행 결과를 즉시 확인"

### 현재 문제점
- 폴링 타임아웃이 무음 (실행 중인지 타임아웃인지 구분 불가)
- "크롤러 추가" 버튼이 안내 모달만 표시 (실제 생성 불가)
- 벌크 작업 없음 (여러 개 동시 실행/비활성화)
- 설정 폼 유효성 검증 없음
- 실행 중인 크롤러 시각적 구분 부족

### 개선 방안

[기획자A]: 각 크롤러 카드에 "마지막 실행" + "수집 건수" + "성공률" 3개 핵심 지표만 보여주자.
[기획자B]: 실행 중에는 프로그레스 바 + 실시간 로그 스트리밍이 있어야 한다. 타임아웃이면 "타임아웃됨" 명확히 표시.
[기획자C]: 카테고리별 그룹핑 (마트/핫딜/쇼핑/공공)으로 관리 편의성 높이자.
→ 합의: 카테고리 그룹핑 + 실행 상태 프로그레스 바 + 타임아웃 명확 표시 + 벌크 선택

### 필수 기능
- P0: 실행 중 프로그레스/스피너 + 타임아웃 명확 표시
- P0: 실행 결과 즉시 표시 (수집 N건, 소요시간, 성공/실패)
- P0: 카테고리별 그룹핑 뷰
- P1: 벌크 선택 (전체 마트 크롤러 실행 등)
- P1: 설정 폼 유효성 검증 (URL 형식, 숫자 범위)
- P1: 실행 이력 미니 타임라인 (최근 5회)
- P2: 크롤러 추가 위저드 (plugin.yaml 템플릿 기반)

### 운영자 시나리오
> "마트 전단지 업데이트해야지" → 마트 카테고리 선택 → 이마트/홈플/롯데 3개 선택 → "선택 실행" → 프로그레스 바 → 결과 확인 (이마트 277건, 홈플 398건, 롯데 49건)

## 3. 플러그인 관리

### 운영자 목표
"어떤 크롤러가 설치되어 있고, 각각 어떤 설정인지 확인/수정"

### 현재 문제점
- YAML 뷰어에 구문 강조 없음
- 인라인 편집 불가
- 검색/필터 없음
- 난이도 별표(⭐⭐)에 설명 없음
- 실행 중인 플러그인 구분 없음

### 개선 방안

[기획자A]: YAML 보다는 폼 기반 편집이 직관적이다. YAML은 "고급" 탭으로 빼자.
[기획자B]: plugin.yaml 직접 편집은 위험하다. 필드별 폼 + 유효성 검증이 안전하다.
[기획자C]: 카테고리별로 묶고, "비활성" 플러그인은 회색 처리해서 눈에 덜 띄게.
→ 합의: 폼 기반 설정 편집 (기본) + YAML 뷰어 (고급), 카테고리 필터, 비활성 플러그인 시각 구분

### 필수 기능
- P0: 카테고리 필터 (마트/핫딜/쇼핑/공공/위치)
- P0: 활성/비활성 시각 구분 (비활성은 회색)
- P1: 폼 기반 설정 편집 (URL, 지연시간, 최대 수집 수)
- P1: 검색 (플러그인 이름/설명)
- P2: YAML 구문 강조 뷰어
- P2: 새 플러그인 템플릿 생성

## 4. 스케줄 관리

### 운영자 목표
"자동 크롤링 주기를 설정하고, 예정된 실행을 한눈에 확인"

### 현재 문제점
- "실행" 버튼이 작동하지 않음
- 커스텀 cron 식에 대한 미리보기 없음
- 비활성 스케줄 시각 구분 부족
- 다음 실행 시간 실시간 갱신 안 됨

### 개선 방안

[기획자A]: 캘린더 뷰로 이번 주 크롤링 일정을 보여주면 직관적이다.
[기획자B]: cron 대신 "매일 7시", "6시간마다" 같은 한국어 프리셋이 더 편하다. 고급은 cron 직접 입력.
[기획자C]: 스케줄 충돌 감지가 필요. 같은 시간에 5개 크롤러가 동시에 돌면 서버 부하 걸린다.
→ 합의: 한국어 프리셋 기본 + cron 고급 입력, 실행 버튼 작동, 타임라인 뷰

### 필수 기능
- P0: "즉시 실행" 버튼 작동
- P0: 한국어 프리셋 확장 (매일 7시, 매일 19시, 12시간마다 등)
- P0: cron 미리보기 (다음 3회 실행 시간 표시)
- P1: 타임라인/캘린더 뷰 (이번 주 일정)
- P1: 스케줄 충돌 경고
- P2: 스케줄 일시정지/재개

## 5. 로그 뷰어

### 운영자 목표
"크롤링 실행 이력을 검색하고, 에러를 추적하고, 보고서를 내보내기"

### 현재 문제점
- 날짜 검색 없음 (크롤러 이름만 필터)
- CSV 내보내기 필드 불완전
- "부분 성공" 상태 설명 없음
- 타임스탬프 포맷팅 안 됨
- 로그 레벨 구분 없음 (INFO/WARN/ERROR)

### 개선 방안

[기획자A]: 로그는 시간순 기본. 에러만 빨간색으로 강조하면 훑어보기 쉽다.
[기획자B]: 날짜 범위 + 크롤러 이름 + 상태 복합 필터가 필요. 그리고 각 로그 클릭하면 수집된 데이터 샘플도 보여줘야.
[기획자C]: CSV에 모든 필드 포함. 월간 보고서용.
→ 합의: 복합 필터 (날짜+이름+상태), 에러 강조, CSV 전체 필드, 데이터 샘플 미리보기

### 필수 기능
- P0: 날짜 범위 필터
- P0: 에러 로그 빨간색 강조
- P0: 타임스탬프 한국어 포맷 (YYYY.MM.DD HH:mm)
- P1: 로그 상세에서 수집 데이터 샘플 보기
- P1: CSV 내보내기 전체 필드 포함
- P1: "부분 성공" 상태 설명 툴팁
- P2: 실시간 로그 스트리밍 (tail -f 스타일)

## 6. 데이터 검토

### 운영자 목표
"크롤링된 데이터를 확인하고, 품질이 괜찮으면 승인하여 DB로 전달"

### 현재 문제점
- 대용량 데이터 로딩 느림 (페이지네이션 없음)
- 스키마 미리보기 50자 잘림
- 벌크 승인/거부 없음
- 품질 점수 설명 없음
- 에러 표시가 raw 객체

### 개선 방안

[기획자A]: "정상 데이터는 한 번에 승인" 기능이 핵심. 문제 항목만 빨간색으로 하이라이트.
[기획자B]: 데이터 미리보기에서 원본 크롤링 데이터를 그대로 볼 수 있어야 한다. 스키마 검증 결과도 필드별로.
[기획자C]: 승인 워크플로가 빨라야 한다. 277개 이마트 데이터를 하나하나 볼 수는 없으니까.
→ 합의: 벌크 승인 + 문제 항목 하이라이트 + 데이터 전체 미리보기 + 품질 점수 상세 설명

### 필수 기능
- P0: 페이지네이션 (대용량 데이터 대응)
- P0: 벌크 승인/거부 ("정상 전체 승인")
- P0: 데이터 전체 보기 (스크롤 가능 테이블)
- P0: 문제 항목 빨간색 하이라이트 (누락 필드, 이상치)
- P1: 품질 점수 상세 분석 (각 항목별 점수 breakdown)
- P1: 데이터 비교 (이전 크롤링 vs 현재)
- P2: 자동 승인 규칙 (품질 90% 이상이면 자동 승인)

## 공통 개선사항

### UI/UX 원칙
1. **신호등 원칙**: 녹색(정상)/노란색(주의)/빨간색(에러) 3색으로 상태 전달
2. **1클릭 원칙**: 가장 자주 하는 작업은 1클릭으로 완료
3. **한국어 우선**: 모든 UI 텍스트, 날짜 포맷, 에러 메시지 한국어

### 기술 공통
- 모든 API 호출을 client.js를 통해 통일
- 낙관적 업데이트 + 실패 시 롤백
- 로딩 스켈레톤 (스피너 대신)
- 에러 상태 한국어 메시지 + 재시도 버튼
