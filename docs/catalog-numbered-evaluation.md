# 번호 분류 실사용 평가 — pass100

- 대상: 이마트 채소·델리·과일, 홈플러스 액상차. 고유 제목 45개 / 원본 관측 53개.
- 최종 결정: 분류 규칙 14제목, 보류 31제목. 실제 추가는 14관측 / 11상품군·판매 페이지. 미해결 2,330 → 2,316.
- 신규 재수집 14 hit, 변형 입력 42개 거부. 관련 검사 2,009개 + 수집기 79개 통과. 운영 DB·원본 보존. 인증: pass100-numbered-eval.
- 자동 생성한 결정 JSON 4개는 총 21,002자. 상품별 필드·제목·해시를 모델이 다시 작성하지 않았고 선반별 Python 모듈·연결 함수를 추가하지 않았다. 이는 생성 파일 크기이며 토큰 절감량 측정은 아니다.
- 성공 하네스 실행은 69.43초, 전체 단계 로그는 6,010바이트였다. 화면에는 단계 경로와 최종 요약만 반환했다.

## 확인한 한계와 보완

- 기존 보류 계약은 번호 도구가 자동 수집하지 않는다. 과일 가변 중량 계약을 늦게 발견해 pass99가 테스트 단계에서 실패했다. 로그를 보존했고 새 pass100으로 인증했다. 다음 후보 선택 때 해당 선반의 기존 테스트를 먼저 검색한다.
- 장조림 2건은 원재료 분류와 완제품 분류가 충돌했다. 숫자만으로 초안을 보류하고 백업하는 hold-draft 명령을 추가했다. 인증 기준본에 들어간 파일은 수정 거부한다.
- 보류를 다시 만들 필요가 없어 다음 prepare 목록에서 제외된다. 근거 보강 시에는 명시적으로 재검토해야 한다.
- 분류 규칙 통과와 실제 적재는 다르다. 이번 미적재 원문 중 새송이·만가닥은 unit_unresolved, 팽이버섯은 적재 보고서의 assignment_missing 계열 사유다. 팽이버섯의 분류 JSON은 리프를 갖고 있어 보고서 차이의 원인은 후속 확인 대상으로 남긴다.
- 판단 자체가 필요한 애매한 상품, 새 리프 설계, 기존 충돌 계약 확인은 자동화되지 않았다. 전체 재구축 비용도 유지한다.

결론: 반복적인 출력·필드 작성에는 유용하고 기존 검사도 실제 오류를 잡았다. 분류 판단 속도나 전체 토큰 절감률까지 입증한 것은 아니다.
