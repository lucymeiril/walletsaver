# 에이전트 팀 구성

## 개요
WalletSavior는 실리콘밸리 스타트업 조직 구조를 모방한 AI 에이전트 팀으로 개발됩니다.
각 팀은 전담 역할을 수행하며, 문서를 통해 소통합니다.

---

## PM (총괄 매니저)
**역할:** 모든 팀 간 조율, 의사결정, 진행 관리
**산출물:** plan.md, STATUS.md, 의사결정 기록
**권한:** 최종 의사결정, 브랜치/PR 전략, 우선순위 조정

## 기획팀 (Planning Team)

### 기획-UX
- 사용자 플로우, 와이어프레임 작성
- UI/UX 가이드라인 정의

- **산출물:** UX 설계 문서, 와이어프레임

- **산출물:** 데이터 모델 문서, 카테고리 트리

### 기획-API
- API 엔드포인트 설계, 프로젝트 간 계약 정의
- OpenAPI 스펙 작성
- **산출물:** API_CONTRACTS.md

## 개발팀 (Development Team)

### 개발-공유코어 (packages/shared/)
- 모델, 계약, 이벤트, 유틸리티
- 모든 프로젝트가 의존하는 기반 코드
- **담당:** Pydantic 모델, 인터페이스, EventBus

### 개발-웹FE (packages/website/frontend/)
- React UI/UX 구현
- 반응형 디자인 (모바일 + 데스크톱)
- 사용자 플러그인 시스템
- **담당:** 8개 페이지, 공통 컴포넌트, 디자인 시스템

### 개발-웹BE (packages/website/backend/)
- FastAPI 서버, 비즈니스 로직
- 인증/인가 (JWT + OAuth)
- 커뮤니티 기능 (게시판, 댓글, 투표)
- **담당:** API 라우트, 서비스 레이어, 미들웨어

### 개발-크롤러엔진 (packages/crawler-admin/backend/engine/)
- 5-전략 캐스케이드 엔진
- 진단, 안티탐지, 전략 관리
- **담당:** StrategyExecutor, DiagnosticsEngine, AntiDetect

### 개발-크롤러구현 (packages/crawler-admin/backend/crawlers/)
- 각 사이트별 크롤러 플러그인 구현
- 크롤러 레지스트리 (자동 등록)
- **담당:** 17+ 크롤러 플러그인

### 개발-크롤러FE (packages/crawler-admin/frontend/)
- 크롤러 관리 대시보드
- 실시간 상태 모니터링
- **담당:** 5개 관리 페이지

### 개발-DBBE (packages/db-admin/backend/)
- PostgreSQL 스토리지 레이어
- 가격 통계, 카테고리 관리
- 데이터 품질 서비스
- **담당:** 스토리지, 서비스, API

### 개발-DBFE (packages/db-admin/frontend/)
- 데이터 관리 대시보드
- 카테고리/키워드 편집기
- 가격 분석 차트
- **담당:** 6개 관리 페이지

## 테스트/QA팀 (Test & QA Team)

### 테스트-단위
- 모든 함수/클래스 단위 테스트 (pytest, vitest)
- 분기 커버리지 80%+
- **기준:** 모든 코드 TDD 사이클 준수

### 테스트-통합
- 프로젝트 간 API 통합 테스트
- 데이터 파이프라인 검증
- **기준:** API 계약 완전 준수

### 테스트-E2E
- 사용자 시나리오 E2E 테스트 (Playwright)
- 핵심 플로우 자동화
- **기준:** 주요 사용자 시나리오 100% 통과

### QA-보안
- 보안 취약점 점검 (XSS, CSRF, SQL Injection)
- 플러그인 샌드박스 검증
- OAuth 토큰 보안 점검
- **기준:** OWASP Top 10 대응

### QA-성능
- API 응답 시간 벤치마크 (p99 < 500ms)
- 크롤러 동시 실행 성능
- 부하 테스트
- **기준:** 동시 사용자 100명 처리

## 사용자팀 (User Team)

### 사용자-초심자
- 처음 방문한 사용자 관점 피드백
- 3클릭 내 핵심 기능 접근 가능한지 확인
- **기준:** 설명 없이 핵심 기능 사용 가능

### 사용자-고인물
- 가격비교 파워유저 관점 피드백
- 상세 필터, 다중 비교, 데이터 깊이 확인
- **기준:** 기존 핫딜 사이트 대비 우위

### 사용자-접근성
- 다양한 디바이스/브라우저 테스트
- 모바일 ↔ 데스크톱 전환 확인
- **기준:** Chrome, Safari, Firefox / iOS, Android 정상 동작

## 팀 간 소통 프로토콜

### 소통 매체
- **문서**: docs/ 디렉토리의 공유 문서
- **이슈**: error-log/ 에 기록된 문제
- **개발일지**: devlog/ 에 세션별 기록

### 소통 규칙
1. 모든 의사결정은 문서로 남김
2. 팀 간 요청은 API_CONTRACTS.md 기반
3. 버그 발견 시 error-log/에 즉시 기록
4. 기능 완성 시 해당 모듈 README.md 작성
5. 세션 종료 시 devlog 작성 (다음 AI 인수인계)
