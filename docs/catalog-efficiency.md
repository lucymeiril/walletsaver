# 분류 작업 비용 점검

## 확인한 원인

- pass95–97에서 매번 taxonomy 단독 검사 후 하네스가 같은 검사를 다시 실행했다. 하네스는 프로젝트 전체가 아니라 지정한 관련 테스트와 수집기 매칭 검사다.
- 각 run은 9,196관측 전체를 새 사본으로 재구축하고 전체 무결성·멱등성·재수집 검증을 실행한다. 코드를 A부터 Z까지 다시 작성한 것은 아니다. 로컬 계산량 자체와 모델 토큰 사용량은 구분해야 한다.
- 긴 빌드 JSON, 테스트 진행점, 이미 확인한 해시와 누적 일지를 매번 대화에 반환했다. 도구 출력은 이후 모델이 읽는 입력 문맥을 늘린다. 긴 코드 패치와 제목 재작성은 출력도 늘린다.
- 10–20건마다 새 모듈·연결 코드·검사·재구축·문서 갱신·커밋을 반복해 고정 비용이 컸다. 잘못된 실행 경로로 실패한 명령도 재시도 비용을 만들었다.

## 적용

- 하네스의 모든 검사와 DB 보호는 유지. 각 단계 원문은 독점 생성 로그에 보존하고 콘솔은 단계 경로와 최종 수치만 출력한다. 실패는 마지막 25줄/4,000자까지만 노출한다.
- 인증서에 단계별 실행 시간과 로그 바이트를 기록한다. 토큰 수는 측정하지 않으므로 절감률은 주장하지 않는다.
- 재개 문서는 20줄 이내. 과거 기록은 별도 문서에서 필요한 묶음만 검색한다.
- 관련 작은 선반을 묶어 검토한 후 한 번 인증한다. 40–100고유 후보는 작업 목표일 뿐, 근거 없는 분류를 요구하는 수량 기준이 아니다.
- 동일 테스트의 사전 전체 실행을 금지하고, 구체적인 실패 가능성이 있을 때만 좁은 검사를 먼저 실행한다.
- 새 규칙은 기존의 범위 제한 helper와 매개변수 검사를 가능한 한 재사용한다.

## 유지한 비용

전체 사본 재구축과 검사는 아직 유지한다. 증분 빌드·검사 캐시는 이전 상품이 사라지거나 오래된 규칙이 남는 문제가 없는지 별도 동등성 검증이 필요하다. 이번에는 결과 출력과 반복 작업부터 줄였다.

하네스 출력/실패 테스트는 로컬 작은 subprocess로 검사한다. 이 변경만으로 기존 pass97 DB를 다시 만들 필요는 없다. 다음 실제 분류 실행에서 새 인증서와 실행 지표를 생성한다.
