### S-2. v4 배척 (안전 타령 / 자율성 차단 / 운영 통제 과잉)

| v4 권고 | 배척 이유 |
|---|---|
| **"링크 없음/외부/불일치 글은 홈 TOP 노출에서 감점"** | 부분 배척. *알고리즘으로 숨기는 것*은 사용자 자율성 차단 + 불투명. 정답은 **카드에 신뢰 배지를 더 크게 노출**해서 사용자가 보고 판단. 검열 아닌 정보 제공. |
| **"댓글 수 적은 글은 `검증 중` 상태를 카드에 같이 표시"** | 부분 수용. `검증 중` 라벨 자체는 정보 제공이라 OK. 단 이 라벨이 노출 감점의 트리거가 되면 거부. |
| **"운영자가 도메인 매칭을 수정할 수 있는 작은 관리 화면 필요"** | 위치 이전: 본 web 영역 아닌 **db-admin / web-admin sidecar** 책임. v5 web 영역은 화이트리스트 *소스만* `mart_aliases.mart_url_domain`으로 못박고, UI는 다른 영역에 위임. |
| **"인기글의 외부 이미지가 깨지면 작성자에게 수정 요청 알림"** | 수용 — *알림*은 정보 제공. 자동 글 숨김/수정 강요는 거부. |
| **"v4가 다시 제기한 7블록 항상 펼침 멤버 재편" 중 "마트표 3개 초과 시 첫 3개만"** | 수용. 정보 차단 아닌 단계 노출. |
| **"슬롯에 들어가는 위젯이 WalletSavior 개인 데이터를 자동으로 받지 않는다"** | 수용. 정보 자기결정권 영역, 자율성과 충돌 없음. |
| **이미지 업로드 임의 상한 숫자 박기 (v2 재발)** | 배척 유지 (v3와 동일). 다만 v4의 **업로드 흐름 UX(진행률, 실패 재시도, 총 용량 표시)** 는 수용. |
| **"deal_url 미리보기에서 판정 결과를 즉시 보여준다"** | 수용 — 클라이언트 도메인 매칭만 (외부 fetch 의무화 아님). |
| **"링크 외부/마트 불일치 글의 자동 노출 통제"** | 거부. 모든 통제는 신고/모더레이션 수동 경로로. |

**총평**: v4는 v2와 달리 기능을 봉인하지 않는 방향으로 반론했다 — 실제 사용 장면을 더 팠다. 안전 타령 성격은 약했고, 자율성 차단으로 흐를 수 있는 *알고리즘 노출 감점* 1건만 배척. 나머지는 대체로 정당.

### S-3. v4의 v5 결단 질문 5개 — 직답

**Q1. 상품 상세 항상 펼침 3블록을 그대로 둘 것인가?**

**A. 재편한다.** 항상 펼침 = `① 결론 라벨 박스 + ② 마트별 가격표(첫 3행) + ③ 커뮤니티 검증 요약 1줄`. v3의 "관련 게시글 3건 항상 펼침"은 v4 지적대로 가격 결정 동선을 가린다. 관련 게시글 3건은 **검증 요약 1줄 클릭 시 펼침** (예: "💬 12명 검증 · 🔥 8명 진짜 핫딜 · ❌ 2명 비핫딜 [펼치기 ▼]"). 마트표 4행 이상이면 첫 3행 + `[전체 N개 마트 보기]`.

**Q2. 할인율 표시 조건을 표본 수만 볼 것인가, 최근성/구매 가능성/용량 변경까지 볼 것인가?**

**A. 4축 동시 검사.** 조건은 다음 4개 모두 통과해야 `discount_pct` 노출:
1. **표본 수**: 최근 90일 ≥ 10건
2. **최근성**: 마지막 관측이 30일 이내
3. **구매 가능성**: 최근 7일 내 활성 deal_url 또는 마트 가격 1건 이상
4. **용량 신뢰도**: `unit_qty`/`unit`가 파싱 성공 (실패 시 라벨에 `⚠️ 용량 미확정` 같이)

하나라도 실패하면 라벨은 표시하되 `-X%`는 숨기고, 부족 사유를 짧게 노출 (`표본 부족 N건`, `최근 확인 D일 전`, `재고 불확실`, `용량 미확정`). 신상품은 `유사상품 대비 -Y%` 라벨로 분리(별도 산식).

**Q3. 글쓰기 신뢰 배지는 카드에서 몇 개까지 보여줄 것인가?**

**A. 카드 1배지 / 상세 펼침에서 3배지.** 카드(게시판 리스트, 홈 인기글 위젯)에서는 단일 통합 배지:
- 🟢 `검증됨` (공식몰 링크 + 마트 일치)
- 🟡 `검증 중` (링크 없음 / 외부 링크 / 댓글 < 3)
- 🔴 `불일치` (마트명/링크 도메인 다름)

상세에서는 v3의 3종(`공식몰 링크 확인됨` / `링크 없음·외부` / `마트명/링크 불일치`)을 그대로 펼침. `작성자 입력가 기준`은 카드·상세 모두 항상 `제보가 기준`으로 짧게 노출.

**Q4. iframe 슬롯 2개를 v1에 넣는다면 샘플 위젯까지 넣을 것인가?**

**A. 샘플 위젯 1개 동봉 (P0).** v4 지적 수용. 빈 슬롯은 검증 불가능.
- **상품 상세 슬롯 P0 샘플**: 내부 `단위가 계산기` 위젯 (canonical_id/현재가/용량을 받아 g당·ml당·1개당 환산 표시) — iframe으로 띄우되 같은 도메인에서 제공해 모든 흐름 검증 가능.
- **마이페이지 슬롯 P0 샘플**: 내부 `이번 주 찜 상품 가격 요약` 위젯.
- 두 슬롯 모두 **기본 접힘 카드**로 시작 (`외부 위젯 열기` 클릭 시 lazy load). 기본 높이 320px, resize postMessage로 최대 720px까지 확장.

**Q5. 검색/게시판 목록은 페이지네이션, 더보기, 무한 스크롤 중?**

**A. 영역별 분리.**
- 상품 검색/카테고리 — **모바일: `더보기` 버튼**, **PC: 페이지네이션 + URL `?page=N` 보존**
- 게시판 (핫딜/자유) — **페이지네이션 + URL 보존** (정렬·태그 필터 상태 모두 URL)
- 홈 핫딜 TOP — **고정 12개**, 더보기 시 검색 결과로 점프
- 자동완성 — **고정 10개**
- 뒤로가기 시 스크롤 위치 복원

## 1. 프로젝트 맥락 + 웹 영역 책임

**WalletSavior**는 일반 소비자가 식료품·생활용품·연료 등의 "진짜 핫딜"을 **3초 안에** 판단하도록 돕는 가격 비교 + 커뮤니티 검증 서비스다. 사용자 1인 운영(=기획자)이며, 4영역(DB / 크롤러 / AI / 웹)으로 분리되어 있다. **본 영역(Web)은 사용자 만족도의 90%를 짊어진다** — 다른 영역이 아무리 정교해도 첫 화면에서 "쉽네"를 못 느끼면 끝.

### 1-1. 본 영역 책임

| 패키지 | 본 영역인가 | 책임 |
|---|---|---|
| `packages/web-frontend/` | ✅ 전체 | 일반 사용자 SPA (React). 검색/카드/상세/게시판/마이페이지/비교 조합기 |
| `packages/web-api/backend/` | ✅ 전체 | Public + 게시판 API (FastAPI). 상품 DB는 `SnapshotRepo`(read-only)로만, 게시판 DB(`board.sqlite`)는 직접 |
| `packages/db-admin/` | ❌ | 상품 DB 관리 (별 영역) |
| `packages/ai-admin/`, `packages/crawler-admin/` | ❌ | 별 영역 |
| `packages/crawler-core/` | ❌ | 크롤러 코어 |

### 1-2. 다른 영역에 거는 의존 (경계만)

- **DB 영역에 요구**: `price_grade` (P10/P25/P50/P75 + 표본 수 + sufficient + 마지막 관측일), `price_observations` 시계열, `mart_aliases.mart_url_domain`, (가능 시) `wholesale_price`. v5에서는 이 스키마가 들어온다고 가정하고 UI 자리를 박는다.
- **크롤러 영역에 요구**: 활성 deal_url 검증 신호 (구매 가능성 판정용). 없으면 v1은 마지막 관측일로 대체.
- **AI 영역에 요구**: 카테고리 후보 제안 (글쓰기 폼에서 자동매칭 보조). 없으면 v1은 키워드 매칭으로 대체.

## 3. 상품 상세 3계층 설계 (v3 재설계 + v4 보강)

### 3-1. 3계층 + 항상 펼침 멤버 재편 (v4 Q1 답)

```
[계층 1 — 항상 펼침]
  ① 결론 라벨 박스        "🔥 핫딜 — 평소보다 32% 저렴, 지금 살만함"
  ② 마트별 가격표(첫 3행)  마트 / 현재가 / 평소가 / 단위가 / 확인 / 링크
                          → 4행 이상은 [전체 N개 마트 보기]
  ③ 커뮤니티 검증 요약 1줄  "💬 12명 검증 · 🔥 8명 진짜 핫딜 · ❌ 2명 비핫딜 [펼치기 ▼]"
                          → 펼침 시 관련 게시글 3건 + verdict

[계층 2 — 헤더만 보임, 클릭 시 펼침]
  ④ 가격대 게이지 (P10~P75)
  ⑤ 가격 추이 그래프 (최근 6개월, 마트 필터)
  ⑥ 도매가/적정가         ← 데이터 없으면 헤더 자체 숨김
  ⑦ 핫딜러 패널 (P10/P25/P50/P75 + 표본 + sufficient + 단위가)

[하단 액션바 — 항상 노출, 모바일 가로 스크롤]
  [⭐ 즐겨찾기] [🔔 ₩X 이하 알림] [✍ 글쓰기] [🍳 조합 추가]

[모드별 초기 상태]
  초심자  : 계층 1만 펼침
  핫딜러  : 계층 1 + 계층 2 ④⑤⑦ 펼침 (⑥은 데이터 있을 때만)
  펼침 상태는 localStorage 저장 → 다음 방문 시 복원
```

### 3-2. "평소 대비 -X%" 통일 산식 + 엣지 (v4 Q2 답)

**용어 사전 (전 화면 공통, v3 유지)**

| 용어 | 정의 | 출처 |
|---|---|---|
| 평소가 | P50 (최근 90일, 마트 가중치 균등, 시즌 OFF) | `price_grade.p50` |
| 핫딜 기준가 | P10 (동일 모집단) | `price_grade.p10` |
| 지금 최저가 | 최근 N일 관측 최저가 (N = 7→14→30 자동 확장) | `GET /products/{id}/current_low` |
| 제보가 | 글 작성자 입력가 | `Post.deal_price` |
| 표시가격 | 화면 컨텍스트 (아래 표) | — |

**산식 (1개로 통일)**

```
discount_pct = (P50 - 표시가격) / P50 × 100
```

**노출 4축 검사 (모두 통과 시 -X% 노출, 하나라도 실패 시 라벨만 + 사유 텍스트)**

| 축 | 조건 | 실패 시 표시 |
|---|---|---|
| ① 표본 | 최근 90일 ≥ 10건 | `표본 N건 · 참고용` |
| ② 최근성 | 마지막 관측 ≤ 30일 | `최근 확인 D일 전` |
| ③ 구매 가능성 | 최근 7일 활성 링크/마트가 ≥ 1 | `재고 불확실` |
| ④ 용량 신뢰도 | `unit_qty/unit` 파싱 성공 | `⚠️ 용량 미확정` |

**현재가 윈도우 자동 확장 (v4 보강 1)**

```
1차: 최근 7일 → 관측 0 ─→ 2차: 14일 → 관측 0 ─→ 3차: 30일
화면 라벨: "최근 7일 최저가" / "최근 14일 최저가" / "최근 30일 확인가"
홈 TOP에는 윈도우가 30일까지 확장된 상품을 표시 (감점 X, 라벨로 정보 제공)
```

**엣지별 처리**

| 엣지 | v5 처리 |
|---|---|
| 거래량 적음 | 4축 중 ②/③에서 걸러짐. 라벨은 표시, `-X%` 숨김, 표본+최근성 텍스트 |
| 신상품 (P50 없음) | 별도 라벨 `유사상품 대비 -Y%` (동 카테고리 + 용량 유사 상품군의 중위값 사용). `평소 대비`와 라벨 다름 |
| 단종 / 리뉴얼 | ③ 구매 가능성으로 자동 차단. `재고 불확실` 또는 `리뉴얼 감지(이전가 무시)` |
| 용량 변경 | ④에서 걸러짐. 카드/상세 결론 박스에 `단위가 변동` 경고 |

**라벨 임계 (v3 유지)**

```
≥ 25%   🔥 핫딜
≥ 10%   🟢 저렴 (방향 표기: ↓)
-5 ~ 10  🟡 평소 (방향: —)
< -5%   🔴 비쌈 (방향: ↑)
표본/조건 부족: 라벨 + 사유, -X% 숨김
```

색 + 이모지 + 방향 기호(↓—↑) 3중 표기로 색맹 a11y 동시 만족 (v4 §13).

### 4-4. 상품 자동완성 (신뢰 배지 3종 → 카드 1배지)

**글쓰기 폼 흐름**:
1. 본문 또는 별도 입력에서 상품명 타이핑 → `/autocomplete?prefix=` 호출
2. 후보 선택 → `canonical_id` 자동 등록 + 상품 미니카드 미리보기
3. `deal_price` 입력 시 실시간 등급 미리보기 (계산은 §3-2 산식)
4. `deal_url` 입력 시 클라이언트 도메인 매칭으로 즉시 배지 표시 (v4 §B-5 보강)

**배지 통합 (v4 Q3 답)**:

| 위치 | 배지 |
|---|---|
| 카드 (게시판 목록 / 홈 인기글) | 단일 배지 1개: 🟢 `검증됨` / 🟡 `검증 중` / 🔴 `불일치` |
| 글 상세 | 3종 펼침: 🟢 공식몰 링크 확인됨 / 🟡 링크 없음·외부 / 🔴 마트명/링크 불일치 + 작은 글씨 `제보가 기준` |

**판정 (서버, 도메인 매칭만)**:

```
domain = parse(deal_url)
case domain in mart_aliases.mart_url_domain[mart_name]:
    → 🟢 공식몰 링크 확인됨 (카드: 검증됨)
case empty deal_url or domain not in any whitelist:
    → 🟡 링크 없음 / 링크 외부 (카드: 검증 중)
case domain ∈ whitelist but mart_name mismatch:
    → 🔴 마트명/링크 불일치 (카드: 불일치)
```

**카드 추가 신호**: 댓글 < 3 → 카드에 `검증 중` 라벨 같이(노출 감점 X, 라벨로 정보).

**조작 방지 — 자정 메커니즘**:
- ① 배지 (정보 노출)
- ② verdict 3종 댓글 (커뮤니티)
- ③ 신고 → 모더레이터
- **자동 fetch 가격 파싱은 v1 의무화 거부** (v3 유지). v1.5에 화이트리스트 마트 한정 *선택* 보조 (`[이 링크 가격 확인]` 버튼).

### 4-5. "이거 핫딜?" 댓글 위젯

- 글 상세 상단에 `VerdictBar` (현 컴포넌트) 끌어올림 → 한 줄 집계 막대
- 댓글 입력창 위 라디오 `[내 verdict: 🔥핫딜 / ❌비핫딜 / 😐보통]`
- **상품 상세에도 verdict 위젯** — v1은 관련 게시글 verdict 집계만 표시, **상품 단위 자체 verdict 테이블은 P1** (`ProductVerdict(user_id, canonical_id, verdict)`)

### 4-6. 신고 / 모더레이션 흐름 (v4 §9 보강)

```
[신고 클릭]
  ↓ 사유 드롭다운 5개 (스팸/욕설/허위 핫딜/도배/기타) + 자유 입력
[제출]
  ↓ "신고 접수됨" + 알림함에 기록
[모더레이터 처리]
  ↓ 처리됨 / 반려됨
[작성자 알림] (글이 숨김 처리되면 사유 표시)
```

- 같은 사용자가 같은 대상 중복 신고 → 기존 신고 업데이트
- 허위 핫딜 신고는 가격/링크 배지와 연결돼 큐 우선순위 상승
- `banned_at` 사용자 UI: 차단 사용자 로그인 시 "차단된 계정 — 사유: X" 메시지. 차단 사용자의 글은 `is_banned` 배지로 표시(렌더는 유지, 정보 제공)

### 4-7. 게시판 정렬 / 검색 (v4 §8)

**정렬 옵션**:
- 최신순
- 댓글 많은 순
- verdict 핫딜 비율순
- 제보가 할인율순
- 링크 검증됨 우선

**검색 범위**: 제목 + 본문 + 마트명 + deal_url 도메인 + freeform 태그 + canonical 상품명.

URL 상태 보존: `/board/hotdeal?sort=verdict&tag=한우&page=2&q=etc` — 모든 조합이 URL 직링 가능.

### 7-1. 반응형 vs 별도 빌드 결단

## 10. 플러그인 / iframe (사용자 자체 개조)

### 10-1. v1 슬롯 2개 + 샘플 위젯 1개 (v4 Q4 답)

| 슬롯 | 위치 | P0 샘플 위젯 | 모바일 |
|---|---|---|---|
| 상품 상세 하단 | `<ProductDetailPage>` 마지막 | 내부 `단위가 계산기` (canonical_id/현재가/용량 받아 g당·ml당 환산) | 접힘 카드, "외부 위젯 열기" 클릭 |
| 마이페이지 사이드 | `<AccountPage>` 우측 | 내부 `이번 주 찜 상품 가격 요약` | 즐겨찾기 탭 아래 접힘 |

샘플 위젯이 들어가야 슬롯 크기/resize/모바일 배치를 *실제로* 검증할 수 있다 (v4 §C-4).

### 10-2. iframe sandbox (기능 차원 보안)

```jsx
<iframe
  src={pluginUrl}
  sandbox="allow-scripts allow-same-origin"
  loading="lazy"
  referrerpolicy="no-referrer"
  style={{ border: 0, width: "100%", height: minHeight }}
  onLoad={handleLoad}
  onError={handleFail}
/>
```

- 기본 높이 320px, resize postMessage로 최대 720px
- 로딩 지연 시 `외부 위젯 불러오는 중` 별도 placeholder (skeleton 아닌 명시 라벨)
- iframe 로드 실패 시 `위젯을 불러오지 못했습니다` + 재시도 버튼

### 10-3. postMessage 컨텍스트 계약 (v4 §B-8 보강)

**이벤트 (확장)**:
- `{ type: "resize", height }` — 부모가 iframe 높이 조정
- `{ type: "navigate", url }` — 부모 라우터 이동 (화이트리스트 URL만)
- `{ type: "ready" }` — 위젯 로드 완료, 부모가 컨텍스트 송신
- `{ type: "request_context" }` — 위젯이 요청, 부모가 응답

**슬롯별 컨텍스트 (부모 → iframe)**:

| 슬롯 | 자동 송신 데이터 |
|---|---|
| 상품 상세 | `{ canonical_id, product_name, displayed_price, p50, grade }` |
| 마이페이지 | `{ favorite_count, recent_count }` 요약만 — *개인 상세 데이터 자동 송신 X*. 위젯이 추가 요청 시 사용자 명시 동의 필요 |

화이트리스트 외 origin의 postMessage는 무시.

### 10-4. 화이트리스트 + 운영 (v3 유지 + v4 부분 보강)

- 허용 URL = 환경 설정 파일 `web-api/config/plugin_slots.json` (코드 변경 없이 운영자 편집)
- 도메인 매칭 4단계 (`공식몰` / `동일 플랫폼` / `외부` / `불일치`) — v4 §D-2
- 운영자 관리 UI = **db-admin/web-admin sidecar 영역** (본 web 영역 외, 다른 영역에 위임)

### 10-5. 플러그인 마켓

- `/plugins` 라우트 = P1 자리
- 마켓 본격 = P2

## 13. 모듈 경계

### 13-1. 영역 간 흐름

```
[web-frontend (React SPA)]
        │ HTTP only
        ▼
[web-api/backend (FastAPI)]
        │
        ├─ SnapshotRepo (read-only) ── 상품 DB (db-admin 영역 빌드)
        │
        └─ board.sqlite (User/Post/Comment/Report/ModerationLog…)

  ↑ web-api는 상품 DB read-only. 게시판 DB만 쓰기.
  ↑ Post.canonical_id ↔ 상품 캐노니컬은 외래키 없이 문자열 약결합 (현 설계 유지).
```

### 13-2. API contract 안정성

| 영역 | v5 추가 endpoint |
|---|---|
| `web-api` | `GET /products/{id}/history?mart=&days=180` |
|  | `GET /products/{id}/current_low` |
|  | `GET /products/{id}/grade_detail` (핫딜러 모드 lazy) |
|  | `GET /boards/{slug}/posts?freeform=태그&sort=verdict` |
|  | `POST /favorites`, `DELETE /favorites/{type}/{id}` |
|  | `POST /price_alerts` (저장만, 발송 P1) |
|  | `POST /combos` (비교 조합 저장) |
|  | `GET /notifications` (자리만) |

contract 안정성:
- 응답 필드는 추가는 자유, 제거/타입 변경은 web-frontend 동기 PR 필수
- `/products/search` 카드 응답 vs `/products/{id}` 상세 응답 분리 유지

### 13-3. 약결합 보호

- `Post.canonical_id`가 상품 DB에 없어도 글은 살아남고 `매칭 상품 없음`으로 graceful fallback (v1 유지)
- 상품 DB 재빌드 시 게시판 DB 무관

### 13-4. API 클라이언트 단일 게이트

`packages/web-frontend/src/api/client.ts` 단일 파일 유지. 그룹 주석으로 섹션 분리.

### 17-2. 사용자 자율성 보존 (헌법 §4)

- 핫딜러 모드 — 유지
- 플러그인 슬롯 — 유지 + 샘플
- 외부 이미지 렌더 — 유지 + 배지/onError
- 자유 가격 입력 — 유지 + 신뢰 배지
- 자유 카테고리 — 유지 + 정형과 병존
- 운영자 코드 변경 없이 화이트리스트 편집 — 유지

### 17-3. 단, 진짜 *기능 차원* 보안 (UX/자율성 차단 효과 없음) — 유지

- XSS: HTML 직접 입력 렌더 거부, `rehype-sanitize`
- CSRF: 세션 토큰 hash + SameSite 쿠키
- iframe sandbox: `allow-scripts allow-same-origin`
- postMessage origin 검증
- 신고/모더레이션
- 401 공통 핸들러 (세션 만료)

위 6개는 사용자가 모르게 동작하는 인프라 보안이지 *기능 봉인*이 아니다.

WalletSavior 웹 v5는 v1 골격(홈 3블록 / 상품 상세 7블록 / 비교 조합기 / 글쓰기 인라인 이미지+자동매칭 / 초심자·핫딜러 토글 / 모바일 반응형 / 게시판 카드형+자유 카테고리 / 즐겨찾기·마이페이지 / iframe 슬롯)을 그대로 유지하면서, v2가 짚은 진짜 약점(라우트 누락, API 표기, `PriceGauge` 버그, 산식 미정의, 신뢰 배지 부재, 재방문 동기, CSS 토큰/포맷 부채)과 v4가 짚은 실제 사용 장면 마찰(항상 펼침 멤버 재편, 산식 엣지 4종, 배지 인지 과부하, iframe 컨텍스트, 자유/정형 충돌, 검색 성능, 외부 이미지 깨짐, 세션 만료, 게스트 병합, 페이지네이션, SEO/PWA/IME)을 전부 통합 수용했다. 반대로 v2의 "7블록 축소·외부 이미지 렌더 거부·가격 파싱 의무화·임의 상한·OAuth 우선순위 재검토" 같은 자율성 차단 권고와 v4의 "링크 미검증 글 홈 TOP 알고리즘 감점" 같은 불투명 노출 통제는 명시 배척했다. 가격 용어 4종+산식 1개+4축 노출 검사(표본·최근성·구매가능성·용량)로 신뢰를 못박았고, 신뢰 배지를 카드 1개·상세 3개로 분리해 인지 과부하를 풀었고, 7블록을 3계층(항상 펼침 = 결론+마트표 첫 3행+검증 요약 1줄 / 접힘 4 / 모드별 펼침)으로 재배치해 "한 눈에 + 복잡하지 않게"를 동시 만족시켰다. iframe 슬롯 2개는 샘플 위젯 1~2개와 postMessage 4종 컨텍스트 계약을 함께 박아 v1부터 실제 검증 가능하게 했고, 비교 조합기는 프리셋 6개+자유 추가 하이브리드, 모바일은 반응형 단일 SPA+공통 컴포넌트 5종 구체 기준값으로 정리했다. 검증 약한 글은 알고리즘 노출 통제 대신 배지 강화로 처리해 자율성과 신뢰성을 양립시켰다. P0는 v1 11개+v3 15개+v5 17개 = 43개 체크리스트로 정리되었고, 다른 영역(DB/크롤러/AI) 의존은 자리 박기 전략으로 충돌 없이 처리, 사용자 헌법 5룰 전부 통과.
