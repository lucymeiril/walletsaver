## 0. 서문 — v2 응답 정책

### 0-1. v2 약점 지적 중 **수용**할 것 (사실 또는 진짜 운영 구멍)

1. **`/fuels` 라우트 누락** — `FuelStationsPage.tsx` 파일은 있는데 `App.tsx` `<Routes>`에 라우트가 빠져 홈 진입이 깨진다. v1이 "동작 중"으로 본 것은 오류. **v1 P0 체크리스트에 라우트 1줄 추가**로 정정.
2. **fuels API 엔드포인트 표기 오류** — v1은 `/fuels/search`, `/fuels/regions`라 썼지만 실제는 `/fuels/stations`, `/fuels/stations/{id}`, `/fuels/regions`. 단순 사실 정정.
3. **autocomplete 쿼리 파라미터 오류** — v1은 `?q=`라 썼지만 실제 client는 `?prefix=`. 단순 사실 정정.
4. **자동완성 응답의 상품/카테고리 직행이 "백엔드 가능"과 "UI 동작"을 섞었다** — 응답 타입에 `canonical_id`/`category_node_id`가 있지만 현 `SearchBar`는 `/?q=display`만 친다. v1에 "직행 UI 구현 필요" 명시 추가.
5. **`ProductDetailPage`의 `PriceGauge`에 `currentPrice={pg.p50}` 버그** — 현재가 자리에 평소가(P50)가 박힌다. v3 P0에 명시. 상품 상세 API에 "현재가" 필드가 없는 것도 같이.
6. **검색 결과의 "핫딜가"가 P10 분위값** — 사용자는 "지금 살 수 있다"고 오해 가능. **용어 분리는 수용**: `평소가(P50)`, `핫딜 기준가(P10)`, `지금 최저가`(현 관측 최저), `제보가`(글쓰기 입력). 화면마다 어떤 가격을 어디에 박는지 v3 §B-2에서 못박는다.
7. **"평소 대비 -X%" 산식이 정의 안 됨** — 진짜 약점. 카드/상세/글쓰기/검색결과에서 산식이 달라지면 신뢰 즉시 깨진다. v3 §B-2에서 1산식으로 못박는다.
8. **글쓰기 자동 등급 라벨의 출처/링크 신뢰도 표기 부재** — 안전 타령 아니라 **UX 신뢰성** 문제. "작성자 입력가 기준", "링크 없음", "마트명/링크 불일치" 배지는 수용. 단 v2가 권한 "글 등록 전 fetch+가격 파싱" 강제는 거부(§B-3).
9. **즐겨찾기 후 재방문 화면이 v1에서 빈약** — 수용. 알림은 v1.5라도, `/account`에 "내가 찜한 상품 / 최근 본 / 찜한 카테고리 오늘 핫딜" 탭은 v1.
10. **상품 상세에 "알림 받을 가격" 입력 UI 자리는 v1에 둬야 한다** — 수용. 알림 발송은 v1.5라도 저장 자체는 v1.
11. **i18n/포맷 함수 한 곳 모으기** — 수용. `toLocaleString`이 컴포넌트마다 흩어진 건 진짜 부채. `src/lib/format.ts` 단일 모듈 생성.
12. **CSS 변수(`--bg`, `--text`, `--card`, `--accent`) 선깔기** — 수용. 다크 모드 본격 구현은 안 하더라도 토큰만 깔면 나중 전면 갈아엎기 회피.
13. **외부 이미지 URL은 `외부 이미지` 배지 표시** — 수용(기능 차원, 사용자에게 출처가 다르다는 정보 제공). 단 **차단/렌더 거부는 거부**(§J).

### 0-2. v2 권고 중 **배척**할 것 (안전 타령 / 자율성 차단 / 규격화 강제)

| v2 권고 | 배척 이유 |
|---|---|
| **"상품 상세 7블록 → 3블록으로 축소"** | 사용자 헌법은 "복잡하지 않게" **그리고** "필요한 정보는 확실하게 한 눈에". 3블록은 후자 위반. 정답은 7블록 유지 + 우선순위/접힘/모드 토글. v2는 "복잡하지 않게"만 들고 자율성 차단. |
| **"회색 자리표시 블록을 여러 개 두지 마라"** | 데이터가 들어오기 전에 UI 자리부터 잡는 게 v1 전략. 자리표시 보기 싫다고 빼면 도매가/식당/알림 자리가 영영 안 생긴다. 회색이 보기 흉하면 디자인을 고치지, 블록을 빼는 게 아님. |
| **"이미지 사진 10장·장당 5MB" 임의 상한** | 사용자 명시 요구에 없음. 디스크/대역폭 한계가 진짜로 임박했을 때 결정할 운영 파라미터. 기획 단계에서 박는 건 규격화 강제. |
| **"외부 이미지 URL을 본문에 직접 쓰면 링크로만 표시"** | 사용자 자율성 차단. 배지("외부 이미지")까지가 정보 제공. 렌더 거부는 사용자가 본문에 박은 그림이 안 보이게 만드는 검열. 표시되 정보만 충분. |
| **"글쓰기 등록 전 deal_url을 fetch해 가격 파싱·검증"** | 거대한 책임. 마트마다 파서 필요, 파싱 실패 시 글이 막힘. 사용자가 "100원" 입력해서 🔥 라벨 받아도 verdict 댓글 + "작성자 입력가 기준" 배지로 자정된다. v1 의무화 거부. v1.5에서 **선택적** 보조로 검토. |
| **"비밀번호 재설정이 소셜 로그인보다 먼저"** | 운영 우선순위 권고로 위장한 규격화. 어느 쪽이 먼저인지는 운영자(=사용자)가 정함. 둘 다 v1.5라는 위치만 유지. |
| **"OAuth vs 자체 가입 운영 관점 재검토"** 식의 회피 권고 | "신중하게 다시 보세요"는 결단 회피. v1 = 자체 유지. 끝. |
| **핫딜러 모드 기능 단계화를 "구현/테스트 비용"으로 깎기** | 일부 수용(시즌보정·마트가중치 v2단계화는 합리적). 그러나 v2의 함의 — "복잡하니 핫딜러 기능 자체를 줄이자" — 는 배척. 핫딜러 자율성은 사용자 헌법 §4(양립 룰). |
| **"플러그인은 너무 약하니 v1에 iframe 슬롯 1개"** | 이건 수용 방향이지만 v2가 "허용된 URL 목록 + postMessage 이벤트 2~3개만"으로 **사전 규격화**하려는 부분은 거부. v1 = `<iframe sandbox>`로 슬롯만 열고, 허용 URL은 운영자가 채운다(코드 아닌 설정). |

### 0-3. v2의 v3 질문 5개 — 답

**Q1. 상품 상세 기본 화면을 3블록으로 줄인다면?**
**A.** 줄이지 않는다. 7블록 유지. 단 **우선순위 재배치 + 접힘 기본값**으로 "한 눈에 부담 없음"을 만든다. 자세히는 §E.
요지:
- 항상 펼침: [라벨 박스] [마트별 가격표(가격 컬럼 포함)] [관련 게시글 3건]
- 기본 접힘(헤더만 보임): [게이지] [추이] [도매가/적정가] [핫딜러 패널]
- 핫딜러 모드 ON 시: 위 4개 모두 펼침으로 시작
- 블록 자체를 빼는 건 헌법 위반("필요한 정보는 확실하게 한 눈에")

**Q2. 할인율 공식과 가격 용어를 한 장으로 확정.**
**A.** §B-2에서 1산식으로 못박음. 요약:
- 용어 4종 분리: `평소가(P50)` / `핫딜 기준가(P10)` / `지금 최저가` / `제보가`
- 산식 1개: `discount_pct = (P50 - 표시가격) / P50 * 100`
- 화면별 "표시가격" 정의: 카드/검색결과 = `지금 최저가`, 상품상세 결론카드 = `지금 최저가`, 글쓰기 미리보기 = `제보가`, 게시판 카드 = `제보가`
- 표본 부족(<10건) 시 `-X%` 숨김, "표본 N건 · 참고용" 텍스트로 대체

**Q3. 글쓰기 자동 등급 라벨의 출처 표시.**
**A.** §B-3. 글 상단에 **3종 신뢰 배지**를 라벨 옆에 노출. 우선순위: ①링크 신뢰 ②마트 일치 ③가격 출처.
- 🟢 `공식몰 링크 확인됨`: deal_url 도메인이 `mart_aliases.mart_url_domain` 화이트리스트에 매칭
- 🟡 `링크 없음` 또는 `링크 외부`: deal_url 비어 있거나 화이트리스트 외
- 🔴 `마트명/링크 불일치`: deal_url 도메인과 `mart_name`이 다름
- 라벨 자체에는 항상 `작성자 입력가 기준` 작은 글씨
- 자동 검증 fetch는 **하지 않는다** (v2 권고 거부). verdict 댓글이 자정.

**Q4. 비교 조합기는 빈 계산기 vs 프리셋형?**
**A.** **프리셋 + 자유 추가 하이브리드, 프리셋이 1차 진입**. v2가 옳다 — 빈 계산기는 초심자가 못 쓴다. 단 빈 계산기를 없애지는 않는다(핫딜러 자율성). §H 참조.
- 진입 화면: 프리셋 6개(김치찌개/된장찌개/제육볶음/샐러드/카레/파스타) 큰 카드
- 프리셋 선택 → 기본 재료 자동 채워짐 → 사용자는 수량만 조정
- 우측 "재료 직접 추가" 검색바 항상 표시
- 식당 데이터 없으면 사용자가 직접 메뉴 가격 입력해 비교(v2 권고 수용)
- 핫딜러 모드: 단위가/마트 가중치 슬라이더 노출

**Q5. v1에 넣을 최소 plugin/iframe 슬롯 위치.**
**A.** **상품 상세 하단 1개 + 마이페이지 사이드 1개 = 총 2슬롯**. 비교 조합기는 v1.5(아직 데이터 흐름이 안 정해짐).
- `<iframe sandbox="allow-scripts allow-same-origin">` 사용 (XSS 방어는 기능 차원)
- 허용 URL은 환경변수/설정 파일 (코드 변경 없이 운영자 편집)
- postMessage 이벤트는 2개만 정의: `resize`(높이 알림), `navigate`(부모에 URL 전달)
- 슬롯 비어 있을 때는 자리표시 없음 (회색 박스 안 함, 슬롯 자체를 안 그림) — Q1과 다름. 이유: 7블록은 정보 자리, 플러그인 슬롯은 옵션이므로 빈 슬롯은 노이즈.

## B. v1 자기검증 5포인트 + v2 약점 통합 재답변

### B-1. 상품 상세 7블록 vs "복잡하지 않게" — 접힘/우선순위/모드 토글

**결단: 7블록 유지. 단 3계층으로 분리.**

```
[계층 1: 항상 펼침 — 3블록]
  ① 결론 라벨 박스 ("🔥 핫딜 — 평소보다 32% 저렴, 지금 살만함")
  ② 마트별 가격표 (가격 컬럼 포함, v1 마트표 보강)
  ③ 관련 핫딜 게시글 3건 (verdict 집계 줄임)

[계층 2: 헤더만 보임, 클릭 시 펼침 — 4블록]
  ④ 가격대 게이지 (P10~P75 색 막대)
  ⑤ 가격 추이 그래프 (최근 6개월)
  ⑥ 도매가 / 적정가 추정 (데이터 없으면 헤더 자체 숨김 — 회색 자리 아님)
  ⑦ 핫딜러 패널 (P10/P25/P50/P75 4컬럼 + 표본 + 단위가)

[모드별 기본 상태]
  초심자 모드: 계층 1만 펼침, 계층 2는 모두 접힘
  핫딜러 모드: 계층 1 + 계층 2 ④⑤⑦ 펼침, ⑥은 데이터 있을 때만

[하단 액션 바 — 항상 노출]
  [⭐ 즐겨찾기] [🔔 ₩X 이하 알림] [✍ 핫딜 글쓰기]
```

v2의 "회색 자리 빼라" 권고는 부분 수용: 데이터가 영영 안 들어올 가능성(도매가)이면 회색 박스 → **헤더 자체 숨김**으로 격하. 단 추이/게이지/핫딜러 패널은 데이터가 들어올 게 확실하므로 자리 유지.

### B-2. "평소 대비 -X%" 산식 통일 정의

**가격 용어 사전 (전 화면 공통)**

| 용어 | 정의 | 출처 |
|---|---|---|
| `평소가` | P50 (90일, 마트 가중치 균등, 시즌보정 OFF) | `price_grade.p50` |
| `핫딜 기준가` | P10 (동일 모집단) | `price_grade.p10` |
| `지금 최저가` | 최근 7일 관측 중 최저 가격 | `price_observations` 시계열 (v1에 신규 API `GET /products/{id}/current_low`) |
| `제보가` | 게시글 작성자가 입력한 가격 | `Post.deal_price` |
| `표시가격` | 화면 컨텍스트에 따라 위 4개 중 1개 | (아래 표) |

**산식 (1개로 통일)**

```
discount_pct = (P50 - 표시가격) / P50 × 100
표본 < 10건 → discount_pct 숨김, "표본 N건 · 참고용" 텍스트
P50 누락 → discount_pct 숨김, 가격만 노출
```

**화면별 표시가격 매핑**

| 화면 | 표시가격 | 라벨 |
|---|---|---|
| 홈 핫딜 TOP 카드 | 지금 최저가 | "지금 최저가 ₩X · 평소 대비 -Y%" |
| 검색 결과 카드 | 지금 최저가 | 동일 |
| 카테고리 카드 | 지금 최저가 | 동일 |
| 상품 상세 결론 박스 | 지금 최저가 | "지금 최저가 ₩X · 평소 ₩Z 대비 -Y%" |
| 상품 상세 마트표 행 | 마트별 현재가 | "마트가 ₩X · 평소 대비 -Y%" (P50은 전체 평균, 마트가는 그 마트 최근) |
| 게시판 카드 | 제보가 | "제보가 ₩X · 평소 대비 -Y% (작성자 입력)" |
| 글쓰기 미리보기 | 제보가 (입력 중) | "제보가 ₩X · 평소 대비 -Y%" + 라벨 자동 갱신 |

**라벨 임계 (4단계)**

```
discount_pct ≥ 25  → 🔥 핫딜
discount_pct ≥ 10  → 🟢 저렴
-5 ≤ discount_pct < 10  → 🟡 평소
discount_pct < -5  → 🔴 비쌈
```

표본 부족·P50 누락 시 라벨 자체를 표시하지 않고 `⚠️ 표본 부족 (N건)`만.

### B-3. 글쓰기 등급 자동 표시 검증 / 조작 방지

**자동 라벨은 유지. 단 라벨에 출처/신뢰 정보를 같이 박는다.**

글 상단 표시 예:
```
🔥 핫딜  (작성자 입력가 기준)
       🟢 공식몰 링크 확인됨  ← 또는 🟡 링크 없음 / 🔴 마트명/링크 불일치
```

신뢰 배지 판정 (서버측, 단순 도메인 매칭만):
```python
if deal_url is empty: badge = "🟡 링크 없음"
elif domain(deal_url) not in mart_url_whitelist: badge = "🟡 링크 외부"
elif domain(deal_url) in whitelist and matches mart_name: badge = "🟢 공식몰 링크 확인됨"
else: badge = "🔴 마트명/링크 불일치"
```

**v2의 "글 등록 전 가격 파싱 검증"은 거부.**
- 이유: 마트별 파서 비용, 파싱 실패 시 글 막힘, 사용자 검열 효과
- 자정 메커니즘: ①배지 ②verdict 3종 댓글 ③신고 기능 → 모더레이터 처리
- 이게 안전 타령이 아닌 이유: 배지는 정보 제공이지 차단이 아님. 사용자 자율성 보존.

v1.5 검토 항목(의무 아님): 화이트리스트 마트 한정 옵션 파싱 (사용자가 "이 링크 가격 확인" 버튼을 누르면 작동).

### B-4. 비교 조합기 v1 진입 결정 — 사용자 검증 방법

**v1 진입 결정: 유지 (사용자 명시 요구). 단 프리셋형 진입 + 빈 계산기 병존.**

검증 방법(추후 실측, v1 기획 차원에서는 가설 검증 흐름만 박음):
1. 프리셋 클릭률 vs 자유 추가 비율 로깅 (frontend 이벤트 로그)
2. "조합 저장 후 게시판 공유" 클릭률 — 진짜 가치 검증 지표
3. 1주일 후 재방문해서 같은 프리셋 다시 여는 비율 — 재방문 유발 여부

만약 P0 출시 후 2주 안에 프리셋 클릭률이 진입의 50% 미만이면 v1.5에서 비교 조합기 진입점을 홈에서 빼고 마이페이지로 격하. (이건 결단이지 회피가 아님.)

식당 데이터 부재 대응: v2 권고 수용. 사용자 직접 입력 폼 노출 + 입력값 기준 비교.

### B-5. 모바일 — 반응형 vs 별도 빌드

**결단: 반응형 단일 앱. 별도 모바일 SPA 거부.**

v2의 "공통 컴포넌트별 모바일 패턴 5개" 접근 수용:
1. 카드 그리드 (`auto-fill minmax` + 미디어쿼리 컬럼 수 조정)
2. 상단 검색 (모바일 = 풀폭, 자동완성 = 풀스크린)
3. 표 → 카드 변환 (`<768px`에서 마트별 가격표를 카드 스택으로)
4. 필터 → 바텀시트 (모바일에서 카테고리 필터 패널이 화면 하단에서 슬라이드 업)
5. 폼 입력 (글쓰기, 비교 조합기 — 모바일 키보드 가림 보정, `viewport` resize 핸들러)

v1에서 점진 마이그레이션 원칙 유지(인라인 style → CSS 클래스). 단 P0에 위 5개 공통 컴포넌트만 새 CSS로 작성, 나머지 페이지는 그대로. **"부분 모바일 대응이 더 나쁘다"는 v2 우려는 컴포넌트 단위 접근으로 해소** — 페이지 단위가 아니라 컴포넌트 단위면 전 페이지가 동시에 좋아진다.

## C. v1이 사용자 헌법에서 빠뜨렸거나 약한 부분 보강

### C-1. 핫딜 게시판 / 자유 게시판 + 카테고리 지정 + 임의 지정

v1 §E에 이미 포함. v3 보강:
- DB 카테고리(`board_category`) 정렬 우선
- 자유 카테고리(`freeform_category`)는 해시태그식 — **태그 클릭 시 필터 API 필요** (v1 백엔드에 없음, 추가): `GET /boards/{slug}/posts?freeform=한우`
- 카테고리 페이지에서 "이 카테고리 관련 핫딜 글" 사이드 위젯 (`Post.canonical_id` join)

### C-2. 글쓰기 인라인 이미지 (XSS 방어 / 외부 이미지)

**기능 차원 보안은 유지, 안전 타령은 아님.**

| 항목 | v3 결정 |
|---|---|
| 업로드 이미지 인라인 삽입 | "삽입" 버튼 → `[[img:N]]` 자동 삽입 (기존 마커 방식 유지, UX만 개선) |
| 마크다운 본문에 외부 `![](https://...)` | 렌더는 한다. 이미지 옆에 작은 `[외부]` 배지 (기능 차원 정보 제공) |
| 외부 이미지 프록시 | **하지 않는다** (v1 차원에서는). 운영 비용/서버 부하/사용자 자율성. 외부 호스팅 추적 우려는 배지로 충분. v1.5 검토. |
| HTML 직접 입력 | 렌더 안 함 (현 정책 유지, XSS 방어 — 기능 차원) |
| 이미지 MIME/크기 임의 상한 | 운영 시 디스크 한계로 정해라. v1 기획에서 박지 않음. |

### C-3. 적정 핫딜가 자동 제시 (글쓰기 중)

글쓰기 폼에서 `canonical_id` 매칭 + `deal_price` 입력 시:
```
이 상품 평소가는 ₩2,900입니다
입력 ₩1,980은 -32% → 🔥 핫딜 범위
(이 등급은 등록 후 검증 댓글이 붙습니다)
```

핫딜 기준가(P10)와도 비교:
```
참고: 핫딜 기준가 ₩1,890 (최근 6개월 하위 10%)
입력 ₩1,980은 핫딜 기준가보다 약간 높지만 평소 대비 충분히 저렴
```

§B-3의 신뢰 배지가 같이 보이므로 사용자는 "내 글이 어떻게 보일지" 미리 확인.

### C-4. "이거 진짜 핫딜?" 댓글 위젯

- 글 상세 상단에 `VerdictBar` 끌어올림 (현재 코드에 컴포넌트 존재)
- 댓글 입력창 위에 `[내 verdict: 🔥핫딜 ○ ❌비핫딜 ○ 😐보통 ●]` 라디오 (v1 §E-5 유지)
- **상품 상세에도 verdict 위젯 추가** (v1에는 없음): 상품 페이지에서 "이거 평소보다 진짜 싼가요?" 미니 투표. 글 단위 verdict와 별도 테이블 (`ProductVerdict(user_id, canonical_id, verdict, created_at)`) — v1.5. v1에서는 관련 게시글 verdict 집계 표시까지만.

### C-5. 위치 기반 주유소 / 식당 (오피넷 데이터 연결)

- 주유소: v1 동작 (라우트 추가 필요, §A 사실관계). 지도 뷰는 v1.5.
- 식당: v1.5 본격, v1은 비교 조합기에서 사용자 입력 + `/restaurants` 자리만.
- 위치 사용 원칙: 일회성, `pos.coords` 저장 금지 (현 코드 주석 유지).

### C-6. 직접 해먹기 vs 식당 가격 비교 (식당 페이지 v1 진입?)

- 비교 조합기 `/compare` — v1 진입 (§H)
- `/restaurants` 단독 페이지 — v1 자리만, v1.5 본격
- 비교 조합기에서 식당 입력은 v1: 사용자가 메뉴명/가격 직접 타이핑 또는 자주 쓰는 프리셋

### C-7. 옷 쇼핑몰 할인 — v1 vs v1.5

v2 지적 수용. 의류 도메인은 마트 식료품 크롤러 범위 밖.
- v1: 의류 카테고리 자리만 (`board_category`의 핫딜 게시판 하위에 "의류" 항목)
- v1: 게시판 글쓰기로 의류 핫딜 제보 가능 (canonical_id 없어도 자유 텍스트로)
- v1.5: 의류 전용 크롤러 또는 게시판 모니터링 기반 통계
- v2의 "위치 지정 필요" 권고 명시: **의류 핫딜은 v1에서 게시판 중심으로 받는다.** 상품 DB 직접 연결 없음.

### C-8. 배달 — 사용자가 "앱만 있어 불가" 명시 → v1에서 빼고 명시

**v1에서 제외 명시.**
- v1 라우트/페이지/필드 어디에도 배달 도메인 없음
- 게시판 자유 카테고리로 사용자가 "배달 핫딜 후기" 글은 쓸 수 있음 (자유는 자유)
- 시스템 차원의 배달 통합은 v3 로드맵에도 두지 않음 (앱 API 없는 한 불가)

### C-9. 플러그인 (iframe 한정) — UI/UX 사용자 자체 개조

§G에서 자세히. 요지:
- v1: 상품 상세 하단 + 마이페이지 사이드, 총 2슬롯
- v1: `<iframe sandbox>` + 허용 URL 화이트리스트(설정 파일)
- v1: postMessage 2이벤트(`resize`, `navigate`)
- v1.5: 플러그인 마켓 페이지 자리 (실제 등록 흐름은 v2)
- 사용자 자체 개조 = 운영자(=사용자)가 화이트리스트에 URL을 추가하면 슬롯에 뜸. 코드 변경 없이.

### C-10. 핫딜러 상세 조정 — 고급 필터 / 비교 / 디테일

v2 권고 수용(단계화). 핫딜러 패널 v1/v1.5/v2 분리:
- **v1**: P10/P25/P50/P75 4컬럼, 표본 수, sufficient 플래그, 단위가(g/ml/개당)
- **v1.5**: 다중 마트 추이 그래프, 배송비 포함 단위가, 마트별 P10/P50 분리
- **v2**: 마트 가중치 슬라이더(균등/시장점유율/사용자선호), 시즌 보정 ON/OFF

핫딜러 모드 자체는 v1 — 토글, Context, `.pro-only` 클래스. v2의 "기능 단계화" 권고가 모드 자체를 깎으려는 시도라면 거부, 기능 채움 단계화라면 수용.

## D. UI / UX 보강

### D-1. 초심자/핫딜러 모드 토글 — 두 모드 운영 가능성

**운영 가능성 평가:**
- 코드 복잡도: React Context 1개 + `useMode()` 훅 + `.pro-only` CSS 클래스. 컴포넌트 분기 최소. **낮음.**
- 데이터 fetch 차이: 없음. 항상 풍부하게 fetch, UI에서만 가림. 한 번 더 강조.
- 실제 UI 차이:

| 영역 | 초심자 | 핫딜러 |
|---|---|---|
| 카드 한 줄 정보량 | 가격 + 라벨 + 마트 | + P10/P50, 단위가, 표본 |
| 상품 상세 | 계층 1만 펼침 | 계층 1+2 펼침 |
| 검색 필터 | 마트/가격대/등급 | + 단위가 정규화, 표본 부족 제외 |
| 글쓰기 | 매칭+가격+이미지 | + 핫딜 기준가 비교, 단위가 입력 |
| 비교 조합기 | 프리셋만 | + 마트 가중치/단위가 슬라이더 |
| 모드 표시 | NavBar 우상단 `⚙ 핫딜러 OFF` | `⚙ 핫딜러 ON` (배지 강조) |

- 테스트: 핵심 페이지 5개 × 2모드 = 10시나리오. 추가 비용은 있지만 감당 가능.
- 결론: **두 모드 v1 동시 운영 가능.** v2의 "운영 어렵다" 우려는 기능 채움 단계화로 해소.

### D-2. 즐겨찾기 / 알림 v1 진입 결정

- **즐겨찾기 v1 진입** (수용): `FavoriteProduct(user_id, canonical_id)`, `FavoriteCategory(user_id, category_id)` 테이블 신설. 비로그인은 localStorage.
- 마이페이지 `/account` 탭: `내 글` / `내 댓글` / `즐겨찾기` / `최근 본` / `찜한 카테고리 오늘 핫딜`(자동 채움)
- **알림 v1 = 자리만**: 상품 상세에 "₩X 이하 알림" 입력 UI 동작 + DB 저장만. 발송은 v1.5. NavBar 종 아이콘은 자리만(클릭 시 "준비 중").

### D-3. 라이트/다크 모드, a11y, i18n

- **CSS 토큰** (v1): `--bg`, `--text`, `--text-muted`, `--card`, `--accent`, `--border`, `--success`, `--warning`, `--danger`. 전역 `:root` + `[data-theme="dark"]` 오버라이드. 본격 다크 토글은 v1.5.
- **a11y** (v1 최소):
  - 검색바/자동완성: 키보드 Up/Down/Enter, ARIA listbox
  - 필터 바텀시트: 포커스 트랩, Esc 닫기
  - 표→카드 변환 시에도 데이터 셀에 `aria-label`
  - 색만으로 라벨 구분 금지: 🔥/🟢/🟡/🔴 이모지로 보조 (이미 v1에 반영)
- **i18n**:
  - 한국어 우선
  - 포맷 함수 단일 모듈 `src/lib/format.ts`: `formatPrice(n)`, `formatPct(n)`, `formatDate(d)`, `formatRelative(d)`
  - 문자열은 인라인 한국어 유지 (`react-i18next` 같은 라이브러리 v1 미도입). 단 라벨/상태 문구는 `src/lib/strings.ts`로 모음 → 추후 i18n 도입 시 1곳만 갈음.

| 동작 | 비로그인 | 로그인 |
|---|---|---|
| 보기 (홈/검색/상세/게시판) | ✅ | ✅ |

## E. 상품 상세 7블록 재설계

### E-1. 진짜 7블록 필요한가? 우선순위 재조정

필요. 단 3계층(§B-1). 우선순위 재배치:

| # | 블록 | 계층 | 사용자 가치 |
|---|---|---|---|
| 1 | 결론 라벨 박스 | 1 (항상) | "지금 사도 되나" 즉답 |
| 2 | 마트별 가격표 (가격 컬럼) | 1 (항상) | 어디서 사나 즉답 |
| 3 | 관련 게시글 3건 + verdict | 1 (항상) | 사람들 검증 |
| 4 | 가격대 게이지 | 2 (접힘 기본) | "얼마나" 시각화 |
| 5 | 가격 추이 그래프 | 2 (접힘 기본) | "최근 어떻게" |
| 6 | 도매가/적정가 | 2 (데이터 시) | "원가 대비" — 핫딜러 |
| 7 | 핫딜러 패널 | 2 (모드 ON 시 펼침) | 분위값/단위가/표본 |

### E-2. 접힘 / 탭 / 스크롤 결단

**접힘(아코디언) + 단일 컬럼 세로 스크롤.**
- 탭은 거부: 정보가 숨겨지면 0학습 룰 위반
- 사이드 컬럼은 거부: 모바일에서 깨짐, 단일 컬럼이 반응형 단순
- 접힘은 헤더 클릭 시 펼침. 펼침 상태는 localStorage에 저장 (다음 방문 시 같은 상태)
- 핫딜러 모드는 §B-1 표대로 초기 상태 결정

### E-3. 초심자 vs 핫딜러 모드 차이

```
초심자:
  계층 1 펼침 (라벨, 마트표, 관련글)
  계층 2 헤더만 ("가격 추이 보기 ▼", "근거 자세히 ▼")
  마트표는 4컬럼: 마트 / 현재가 / 평소가 / 링크

핫딜러:
  계층 1 + 계층 2 ④⑤⑦ 펼침
  마트표는 7컬럼: 마트 / 현재가 / 평소가(P50) / 핫딜 기준가(P10) / 단위가 / 확인 / 링크
  추이 그래프에 도매가 라인 표시 (데이터 시)
  핫딜러 패널의 P10/P25/P50/P75 표 펼침 + 표본 수 + sufficient 플래그
```

## F. 게시판 보강

### F-1. 핫딜 / 자유 분리 + 카테고리 + 인라인 이미지 + 자동 등급

- 분리: 유지 (v1 §E)
- DB 카테고리 + 자유 카테고리: 병존 (v1 유지)
- 자유 카테고리 클릭 필터: **v3 신규 — 백엔드 추가** `GET /boards/{slug}/posts?freeform=태그`
- 인라인 이미지: 업로드 → 본문 삽입 버튼 → `[[img:N]]` 자동
- 자동 등급 표시: §B-3 (라벨 + 신뢰 배지 + "작성자 입력가 기준")

### F-2. XSS / 이미지 프록시 (기능 차원)

- HTML 직접 입력 렌더 거부 (현 정책 유지) — 기능 차원
- `ReactMarkdown` 사용 시 `rehype-sanitize` 추가 검토 (v1) — 기능 차원
- 외부 이미지 URL: 렌더는 함 + `[외부]` 배지 (정보 제공, 차단 아님)
- 이미지 프록시 서버: v1 안 함 (운영 비용)

### F-3. 댓글 "이거 핫딜?" 위젯

- 글 단위 verdict 3종 (현 코드)
- 글 상단 `VerdictBar` 끌어올림
- 댓글 입력창 위 라디오 (v1 §E-5)
- 상품 단위 verdict는 v1.5 (스키마 추가 필요)

### F-4. 신고 / 모더레이션 흐름

- 신고 버튼: 글/댓글 상세에 아이콘 (현 backend `/posts/{id}/report`, `/comments/{id}/report`)
- 신고 사유: 자유 입력 + 사전 정의 5개(스팸/욕설/허위 핫딜/도배/기타) 드롭다운
- 모더레이션 큐: `/admin` 영역(본 기획 외, sidecar). 단 v3에서 자유 카테고리 신고 시 모더레이터에게 노출되도록 백엔드 확인 필요
- `banned_at` UI: 차단 사용자가 로그인 시 "차단된 계정입니다 — 사유: X" 메시지 (v1)
- 차단 사용자의 글: 표시되지만 "이 사용자는 차단되었습니다" 배지 (현 backend `is_banned` 필드 확인)

## G. 플러그인 / iframe

### G-1. 사용자 자체 개조 메커니즘

- v1 슬롯 2개:
  1. **상품 상세 하단** (`<ProductDetailPage>` 마지막 블록)
  2. **마이페이지 사이드** (`<AccountPage>` 우측 사이드바)
- 슬롯에 들어갈 URL은 환경 설정 파일(`web-api/config/plugin_slots.json`) — 코드 변경 없이 운영자 편집
- 사용자(=운영자, 1인) 자체 개조 = 이 JSON 편집 + 화이트리스트 도메인 추가

### G-2. iframe sandbox (기능 차원)

```html
<iframe
  src={pluginUrl}
  sandbox="allow-scripts allow-same-origin"
  loading="lazy"
  referrerpolicy="no-referrer"
  style={{ border: 0, width: "100%" }}
  onLoad={handleLoad}
/>
```

- `allow-scripts allow-same-origin` 둘만 (XSS 방어, 폼/팝업/탑네비 차단)
- postMessage 2이벤트:
  - `{ type: "resize", height: number }` — 부모가 iframe 높이 조정
  - `{ type: "navigate", url: string }` — 부모 라우터에 SPA 이동 (화이트리스트 URL만)
- 화이트리스트 외 origin의 postMessage는 무시

### G-3. 플러그인 마켓 v1에 자리만

- `/plugins` 라우트 — v1.5
- v1: 슬롯 2개만 동작, 마켓 페이지 없음
- v2: 사용자가 플러그인 검색/설치/리뷰

### H-1. v1 vs v1.5+ 재결단

**비교 조합기 `/compare` — v1 진입 확정.**

- 결과 박스: 직접 만들기 vs 식당 평균 vs 사용자 입력 식당가
- 조합 저장 (로그인 시): `Combo(id, user_id, name, items_json, created_at)` 테이블

**식당 `/restaurants` — v1 자리만, v1.5 본격.**
- v1: 페이지 라우트 + `Restaurant` 타입 정의 + "준비 중" 자리표시
- v1.5: 네이버 플레이스 또는 카카오맵 연동 (외부 API 약관/비용 확정 후)
- v1에서 비교 조합기 안에서는 사용자 입력 기반 식당 비교는 동작

### H-2. 핵심 경로 (검색 → 조합 → 식당가 비교)

```
[홈]
  ↓ 검색 "김치찌개" 또는 "두부"
[검색 결과]
  ↓ 상품 카드 클릭
[상품 상세]
  ↓ "비교 조합기에 추가" 버튼 (v3 신규)
[비교 조합기]
  ↓ 재료 자동 채움 또는 프리셋 선택
[결과: 직접 만들기 ₩7,170 vs 식당 평균 ₩9,000]
  ↓ "이 조합 게시판에 공유" 버튼
[글쓰기, canonical_id 묶음 자동 등록]
```

- "비교 조합기에 추가" 버튼은 상품 상세 액션 바에 추가 (`⭐ 즐겨찾기 / 🔔 알림 / ✍ 글쓰기 / 🍳 조합에 추가`)
- 4버튼이 모바일에서 한 줄로 가로 스크롤

## J. 안전 타령 배척 선언

### J-1. 명시 배척 — v2가 들이밀었거나 들이밀 만한 회피 권고

1. **"상품 상세 7블록은 복잡하니 3블록으로 줄여라"** — 배척. 헌법은 "필요한 정보는 확실하게 한 눈에". 3블록 강제는 정보 차단. 정답은 접힘/우선순위/모드.
2. **"외부 이미지 URL은 본문에 직접 쓰면 렌더 거부"** — 배척. 사용자 자율성 차단. 배지로 정보 제공이 충분.
3. **"글 등록 전 deal_url 자동 fetch + 가격 파싱 검증 의무화"** — 배척. 거대한 책임/마트별 파서/파싱 실패 시 글 막힘. v1.5에서 **선택적** 보조로만.
4. **"이미지 사진 10장·장당 5MB" 임의 상한** — 배척. 사용자 명시 요구 없음. 운영 단계 파라미터를 기획에 박지 않음.
5. **"OAuth vs 자체 가입을 운영 관점으로 다시 보세요"** — 배척. 결단 회피. v1 = 자체 유지.
6. **"비밀번호 재설정이 소셜 로그인보다 먼저"** — 배척. 운영자(=사용자)가 정함.
7. **"핫딜러 모드 운영 어려우니 기능을 줄이자"** 식의 함의 — 배척. 단계화는 수용하되 모드 자체는 v1.
8. **"플러그인 허용 URL/postMessage 이벤트를 사전 규격으로 강제"** — 배척. 슬롯만 열고 운영자가 채움. 코드 아닌 설정.
9. **"회색 자리표시 블록을 여러 개 두지 마라"** — 부분 배척. 영영 안 들어올 데이터(도매가 일부)는 헤더 숨김, 그 외는 자리 유지. 빈 블록 보기 싫다고 미래 자리를 안 잡으면 영영 안 생긴다.

### J-2. 사용자 자율성 차단 배척

- 핫딜러 모드 제거 — 거부
- 플러그인 봉인 — 거부
- 외부 이미지 차단 — 거부
- 글쓰기 가격 입력 제한 — 거부 (배지로 충분)
- 비교 조합기 자유 추가 제거 (프리셋만) — 거부

### J-3. 단, 진짜 기능 차원 보안은 유지

- XSS: HTML 직접 입력 렌더 거부, `rehype-sanitize`
- CSRF: 세션 토큰 hash + SameSite 쿠키 (현 코드 유지)
- iframe sandbox: `allow-scripts allow-same-origin`만
- postMessage origin 검증
- 신고/모더레이션 기능

이 4개는 안전 타령이 아닌 **기능 차원 보안**. UX/자율성 차단 효과 없음.

| 0학습 룰 | ✅ | 이모지 라벨 + 한국어 한 줄 + 신뢰 배지 |
| 양립 룰 | ✅ | 핫딜러 모드 토글 + Context + 단계화 |
| 검증 가능 룰 | ✅ | 게이지 + 추이 + 표본 + verdict + 신뢰 배지 |

**위반 없음.**

### K-3. v4가 깔만한 약점 (3~5개)

1. **현재가 API (`/products/{id}/current_low`)의 "최근 7일" 윈도우가 임의 결정** — v4는 "왜 7일? 14일/30일이면 다르지 않냐? 마트별로 갱신 주기 다르면 7일이 노이즈 아니냐?"고 깔 수 있다. 답 대비: 7일은 시작값, 실측 후 조정. 백엔드에 윈도우 파라미터 노출.

2. **신뢰 배지 화이트리스트(`mart_url_whitelist`) 운영 관리 비용** — 마트가 도메인 바꾸거나 새 마트 추가 시 화이트리스트 업데이트 안 하면 🔴 오판정. v4는 "운영 부담"으로 깔 수 있다. 답 대비: `mart_aliases` 테이블에 `mart_url_domain` 컬럼이 이미 있음, 그걸 화이트리스트 소스로 사용.

3. **비교 조합기 프리셋 6개의 근거** — 김치찌개/된장찌개/제육볶음/샐러드/카레/파스타가 왜 이 6개? 가성비 사용자 페르소나 정의 안 됨. v4는 "데이터 기반 아니다"라고 깔 수 있다. 답 대비: P1에 실측 클릭률 기반 재정렬 명시.

4. **iframe 슬롯 2개의 위치(상품 상세 하단 + 마이페이지 사이드)가 어떤 플러그인을 상정한 것인지 불명** — v4는 "쓰지도 않을 슬롯을 왜 박나"고 깔 수 있다. 답 대비: 첫 플러그인 후보(가계부 임포트, 영수증 OCR, 외부 가격 계산기) 명시 필요 — v3는 자리만, 후보 매핑은 v1.5.

5. **모바일 공통 컴포넌트 5종이 실제 디자인 사양 없이 "패턴"으로만 정의** — v4는 "와이어 없이 어떻게 구현?"이라고 깔 수 있다. 답 대비: 와이어는 v1 본문 §C에 있음, v3는 골격만. 실제 디자인은 구현 단계 책임.

6. **자유 카테고리 필터 API 추가가 백엔드 변경을 동반하는데 본 기획 범위에 들어가는가** — v4는 "백엔드 변경은 다른 영역 침범"이라고 깔 수 있다. 답 대비: web-api는 본 기획 범위(`packages/web-api/backend/`). 침범 아님.

## L. 본문 한 문단 요약

WalletSavior 웹 v3는 v1 골격(홈 3블록 / 상품 상세 7블록 / 비교 조합기 / 글쓰기 인라인 이미지·자동매칭 / 초심자·핫딜러 토글 / 모바일 반응형 / 게시판 카드형 + 자유 카테고리 / 즐겨찾기·마이페이지 / iframe 슬롯)을 유지하면서, v2가 짚은 진짜 약점(`/fuels` 라우트 누락, API 표기, `PriceGauge` 버그, "평소 대비 -X%" 산식 미정의, 글쓰기 신뢰 배지 부재, 자동완성 직행 UI, 재방문 동기 부족, CSS 토큰/포맷 모듈 부채)을 모두 수용해 살을 붙였다. 반면 v2의 "7블록을 3블록으로 줄여라", "외부 이미지 렌더 거부", "deal_url 가격 파싱 의무화", "이미지 임의 상한", "핫딜러 모드 운영 어렵다" 같은 안전 타령·규격화 강제·자율성 차단은 명시 배척했다. 가격 용어 4종(평소가/핫딜 기준가/지금 최저가/제보가)과 산식 1개로 신뢰를 못박았고, 신뢰 배지 3종으로 글쓰기 등급 조작 우려를 차단(검열 아닌 정보 제공으로), 7블록을 3계층(항상/접힘/모드별 펼침)으로 재배치해 "한 눈에 + 복잡하지 않게"를 동시에 만족시켰다. 비교 조합기는 프리셋+자유 하이브리드로 초심자 진입을 낮추고, iframe 슬롯 2개와 설정 파일 기반 화이트리스트로 사용자 자체 개조 자율성을 v1부터 보장했다. P0 체크리스트는 v1 11개 + v3 15개 추가 항목으로 정리.
