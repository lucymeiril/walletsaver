# 다음 모델을 위한 짧은 실행 안내

모델/추론 설정은 사용자가 바꾼다. 낮은 추론 설정을 신뢰도 보증으로 취급하지 않는다. 대화가 압축되어도 아래 파일과 명령이 기준이다.

짧은 저장소 지침은 [OpenAI의 AGENTS.md 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md)를 참고했다. 안전성은 문서 준수만으로 보장하지 않으며 아래 실행 검사와 별도로 판단한다.

## 시작

1. `AGENTS.md` → `docs/RESUME_CHECKPOINT.md` → `docs/catalog-state.json`만 읽고 시작한다. 과거 보고서 전체나 원본 대형 JSON을 출력하지 않는다.
2. `git status --short`로 사용자 변경을 확인한다. `py tools/catalog_harness.py preflight` 실패 시 이유를 해결하기 전 빌드를 하지 않는다. 운영DB로 대체하거나 기준 해시를 조용히 갱신하지 않는다.
3. 다음 범위는 **과일청차 / 과일농축액 / 삼계재료**. 기존 pass45 remaining의 묶음101·103·104가 주된 입력이며 최신 pass46 delta의 이미 반영된 ID를 제외한다. 이전 제안은 근거이지 정답이 아니다. 이 셋 이외의 전량 순회·제안 문서 정리는 하지 않는다.

## 한 묶음의 완료 조건

- 원문에서 상품형태를 확인한다. 과일청차와 주스/농축액, 조리재료와 완성 삼계탕을 구분한다. 모호하면 보류한다. 루트 포함4단계 리프만 추가한다.
- 수정 대상은 `initial_product_forms.py`와 그 테스트를 우선한다. 기존 후보/충돌을 무시하는 코드, 광범위한 별칭, 가격·묶음수량 추정은 추가하지 않는다. 새 리프 개수를 맞추려고 테스트 숫자만 바꾸지 않는다.
- 정상 예시, 유사하지만 다른 상품, 잘못된 문맥, 혼합묶음을 테스트한다. 실제 영향받는 원문 제목 목록을 먼저 확인한 뒤 빌드한다. 규칙을 수정하면서 이미 돌고 있는 빌드를 승인하지 않는다.
- `py tools/catalog_harness.py run --run-id initial-catalog-<날짜>-<새이름>` 실행. 도구가 정한 관련 테스트→새 사본→DB검증→매칭회귀→기존행/431결정/해시검사 순서를 따른다. 실패한 출력은 남기고 새 이름으로 다시 실행한다.
- `checks-passed.json`이 없거나 코드/산출물 해시가 달라졌으면 검증 완료가 아니다. 이것은 분류 의미의 정확성이나 공개 승인까지 보증하지 않는다. 예상 밖 분류 영향은 원문을 확인한다.
- 통과 후 한 재개 문서에 실제 추가ID·남은수·출력 경로·다음 범위를 적는다. 새 DB를 Git에 올리지 않는다. 다음 기준 DB로 승격하려면 certificate를 확인하고 catalog-state의 baseline/두 count를 함께 갱신한다. 원본/431결정 기준은 바꾸지 않는다. 승격으로 state 해시가 달라지면 이전 certificate의 당시 상태라는 점을 남긴다.

## 하지 말 것

원본DB·비밀키·기존사본 수정/삭제, 자동 공개, GitHub 채팅 외주 재시작, 전체 handoff 재복제, 완료율 수작업 합산, 미실행 검사 완료 보고, 에이전트의 “완료”만 믿고 합치기.

하위 에이전트가 필요하면 읽을 JSON 경로와 결과 범위를 명시한다. SQLite/Git/네트워크 접근을 맡기지 않는다. 작은 명령 하나를 대신 실행시키려고 에이전트를 만들지 않는다.
