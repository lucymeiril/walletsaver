# 사용자 관점 UX 분석 보고서
> WalletSavior(지갑 지키미) 프론트엔드 — 2025년 분석

---

## 종합 평가

**전체 UX 수준: B− (양호하나 치명적 문제 존재)**

사이트의 정보 구조와 기능 설계는 우수하나, 실제 한국 소비자가 처음 접했을 때 **"이걸 어떻게 쓰지?"** 라는 반응이 나올 가능성이 높다. 핵심 문제는 다크 모드 강제 적용, 불완전한 네비게이션, 그리고 초보 사용자를 위한 가이드 부재이다.

### 🔴 가장 큰 문제점 3개

1. **다크 모드 기본값** — 한국 쇼핑/물가 비교 사이트에서 다크 모드는 매우 이질적. 네이버, 쿠팡, 뽐뿌 모두 라이트 모드. 40대 주부(박서연)가 이 사이트를 열면 "이게 뭐지?" 하고 바로 이탈할 가능성 높음. 라이트 모드 토큰은 정의되어 있으나(`tokens.css` L185–L202) 전환 UI가 없음.

2. **하단 네비게이션에서 '동네물가' 페이지 누락** — `BottomNav.jsx`에 5개 탭(홈/물가비교/핫딜/마트/더보기)만 있고, '동네물가(LocalPage)'가 빠져 있음. 모바일 사용자(최수아, 23세)는 주유소 가격을 찾으려면 상단 헤더 메뉴를 열어야 하는데, 하단 네비게이션이 있는 모바일에서 상단 메뉴를 여는 사용자는 거의 없음.

3. **신규 사용자 온보딩 제로** — 사이트에 처음 들어온 김민지(28세)에게 "물가비교가 뭔지", "핫딜을 어떻게 활용하는지", "DB 대비가 무엇인지" 설명하는 UI가 전혀 없음. 전문 용어("DB 대비", "고인물 모드", "가격 등급")가 설명 없이 사용됨.

### 🟢 가장 좋은 점 3개

1. **구매 타이밍 판단 시스템** (`PricePage.jsx` L107–L111) — "역대급 기회!", "지금 사도 괜찮아요!", "조금 기다려보세요" 등의 자연어 판단은 **매우 직관적**. 한국 소비자가 정말 원하는 핵심 정보.

2. **고인물 모드 (Progressive Disclosure)** (`PricePage.jsx` L259–L279) — 초보자에게는 간단한 UI, 전문가에게는 상세 통계를 토글로 제공. 두 사용자 그룹 모두 만족시키는 훌륭한 설계.

3. **커뮤니티 가격 자동 검증** (`CommunityPage.jsx` L40–L41, L56–L59) — 사용자가 가격을 입력하면 DB와 자동 비교하여 허위 가격을 차단. 커뮤니티 정보 신뢰도를 크게 높이는 차별화 기능.

## 페이지별 상세 분석

### 1. 홈 페이지 (HomePage)

**현재 상태:** 히어로 검색 → 카테고리 → 핫딜 → 물가 → 마트 세일 → 주유소 → 커뮤니티 순으로 구성. 정보 밀도가 높고 스크롤이 긺.

**좋은 점:**
- 히어로 카피 "이 가격, 진짜 싼 건가요?"는 사용자의 핵심 질문을 정확히 반영 (`HomePage.jsx` L55)
- 검색 자동완성이 상품 아이콘, 카테고리, 가격까지 표시 (`HomePage.jsx` L78–L89)
- 인기 검색어와 최근 검색 표시가 검색 시작점으로 좋음 (`HomePage.jsx` L93–L126)
- 물가 카드에 관심 등록(하트) 기능 포함 (`HomePage.jsx` L226–L229)
- 마트 탭 전환으로 이마트/홈플러스/롯데마트/코스트코 세일을 홈에서 미리보기 가능

**문제점:**

| # | 문제 | 위치 | 심각도 |
|---|------|------|--------|
| 1 | **quickTags와 TRENDING 데이터 중복** — '양파', '삼겹살' 등이 quickTags(L44)와 TRENDING(L8) 양쪽에 존재. 사용자가 같은 키워드를 두 곳에서 보면 혼란 | `HomePage.jsx` L8, L44 | 중 |
| 2 | **recentChips가 히어로 하단에 별도 표시** — 검색 포커스 시 드롭다운에도 최근 검색이 나오고, 히어로 하단에도 또 나옴. 중복 UI | `HomePage.jsx` L138–L150 | 중 |
| 3 | **주유소 섹션에 "현재 위치 기준"이라 쓰여 있지만 실제로는 위치 미사용** — 모든 사용자에게 같은 데이터가 보임. 위치 미동의 시 오해 유발 | `HomePage.jsx` L282 | 높 |
| 4 | **카테고리 '배달'이 커뮤니티로 연결** — 배달 카테고리를 클릭하면 /community로 이동하는데, 사용자는 배달 앱 가격 비교를 기대함 | `HomePage.jsx` L16 | 중 |
| 5 | **홈의 커뮤니티 글을 클릭하면 무조건 /community로만 이동** — 해당 글의 상세 보기로 직접 가지 않음. 클릭한 글이 아닌 전체 목록이 뜨면 사용자 실망 | `HomePage.jsx` L311 | 높 |
| 6 | **핫딜 카드 클릭도 /hotdeal 전체 페이지로만 이동** — 상세 모달이 아닌 페이지 전환. 홈에서 관심 핫딜 클릭 → 전체 목록 표시는 UX 끊김 | `HomePage.jsx` L188 | 높 |
| 7 | **모바일(360px)에서 카테고리 6개가 3x2 그리드** — 아이콘+텍스트가 꽤 작아짐. 터치 타겟은 44px 확보했으나 시각적으로 빡빡함 | `HomePage.module.css` L449, L463 | 낮 |

**개선 제안:**
- quickTags를 제거하고 TRENDING만 유지하거나, quickTags를 카테고리별로 분류
- recentChips를 히어로 하단에서 제거 (검색 드롭다운에서만 표시)
- 주유소 섹션 문구를 "서울 주요 주유소" 등 일반적 표현으로 변경하거나, 실제 위치 동의 프로세스 추가
- 홈의 핫딜/커뮤니티 카드 클릭 시 해당 상세 모달이 바로 열리도록 변경

### 2. 핫딜 페이지 (HotdealPage)

**현재 상태:** 카테고리 필터 + 출처 필터 + 정렬 옵션 + 무한 스크롤 그리드. 상세 모달에 가격 차트와 댓글 기능.

**좋은 점:**
- 뽐뿌/어미새/루리웹/에펨코리아 출처 필터로 다중 커뮤니티 통합 (`HotdealPage.jsx` L9)
- 4단계 할인 등급 (역대급/대박/괜찮은/보통) 배지가 한눈에 판단 도움 (`HotdealPage.jsx` L12–L19)
- "DB 대비" 배지로 수집된 평균 가격과 비교 — 핫딜 고인물에게 매우 유용 (`HotdealPage.jsx` L129–L135)
- 핫딜/아니다 투표 시스템으로 커뮤니티 검증 (`HotdealPage.jsx` L139–L148)
- 상세 모달에 30일 가격 추이 차트 포함 (`HotdealPage.jsx` L223–L244)
- 무한 스크롤로 자연스러운 탐색 경험

**문제점:**

| # | 문제 | 위치 | 심각도 |
|---|------|------|--------|
| 1 | **"DB 대비" 용어가 초보 사용자에게 의미 없음** — "DB"가 무엇인지 설명 없음. "시세 대비" 또는 "평균가 대비"로 바꿔야 함 | `HotdealPage.jsx` L131 | 높 |
| 2 | **투표 상태가 로컬 state** — 페이지 새로고침하면 투표 사라짐. 다른 사용자의 투표 결과도 안 보임. 투표 총계 표시 필요 | `HotdealPage.jsx` L27, L51–L57 | 높 |
| 3 | **댓글 작성에 로그인 체크 없음** — 핫딜 모달에서 비로그인 상태로 댓글 작성 가능(로컬 state에만 저장). 커뮤니티 페이지는 체크함 | `HotdealPage.jsx` L177–L180 | 중 |
| 4 | **썸네일 없는 카드가 텍스트만 표시** — 일부 핫딜에 thumb가 없으면 카드 상단이 비어 불균형. placeholder 이미지 필요 | `HotdealPage.jsx` L111 | 낮 |
| 5 | **모달에서 원본 링크로 이동하는 버튼 없음** — 핫딜의 원래 출처(뽐뿌 등) 페이지로 가는 링크가 없어서 실제 구매 불가 | `HotdealPage.jsx` L183–L271 | 높 |
| 6 | **카드에 배지가 3개까지 나열** — 할인 등급 + % 할인 + DB 대비가 모두 표시되면 배지 영역이 과밀. 모바일에서 특히 문제 | `HotdealPage.jsx` L120–L136 | 중 |

**개선 제안:**
- "DB 대비" → "수집 평균가 대비"로 변경하고, 첫 방문 시 툴팁으로 설명
- 투표 총계를 "🔥 47 / ❄️ 3" 형태로 표시
- 모달에 "원본 보기" 외부 링크 버튼 추가
- 배지 표시를 가장 중요한 1개(할인 등급)만 카드에 표시, 나머지는 모달에서

### 3. 물가 비교 페이지 (PricePage)

**현재 상태:** 상품 미선택 시 전체 상품 그리드 + 검색. 선택 시 좌측에 상세 정보(타이밍 판단, 가격 차트, 등급 바, 전문가 모드), 우측에 마트별 비교 및 관련 핫딜.

**좋은 점:**
- **구매 타이밍 자연어 판단** ("지금 사도 괜찮아요!", "조금 기다려보세요")이 핵심 가치 제공 (`PricePage.jsx` L108–L111)
- **적정 핫딜가** (평균의 80%) 안내로 "이 가격이면 사야 해" 기준선 제시 (`PricePage.jsx` L115, L198–L204)
- **가격 등급 바** 시각화가 직관적 — 현재 가격이 어디에 위치하는지 한눈에 파악 (`PricePage.jsx` L213–L225)
- **속성 변형 선택** (냉장/냉동, 국산/수입)으로 같은 품목의 다양한 조건 비교 가능 (`PricePage.jsx` L176–L189)
- **마트별 수평 바 차트**로 어디가 가장 싼지 시각 비교 (`PricePage.jsx` L285–L302)
- **고인물 모드**의 상세 통계 (평균 할인율, 할인 빈도, 데이터 기간, 신뢰 구간 등)

**문제점:**

| # | 문제 | 위치 | 심각도 |
|---|------|------|--------|
| 1 | **상품 미선택 시 전체 상품(12개)이 나열되지만 카테고리 필터 없음** — 채소/축산/과일이 섞여 있어 원하는 품목 찾기 어려움 | `PricePage.jsx` L71–L92 | 높 |
| 2 | **가격 등급 바 색상이 비직관적** — 빨간색(zoneUltra)이 "역대급"(좋은 가격)인데, 빨간색은 보통 "위험/비쌈"으로 인식됨 | `PricePage.module.css` L239–L242, `tokens.css` L93 | 높 |
| 3 | **가격 박스 4개가 모바일에서 1열이 됨** — 480px 이하에서 4개가 세로 나열되면 과도한 스크롤 발생 | `PricePage.module.css` L425 | 중 |
| 4 | **"관련 핫딜"이 항상 food 카테고리만 표시** — 의류/전자제품을 보고 있어도 식품 핫딜만 나옴. 상품 카테고리와 무관 | `PricePage.jsx` L328 | 중 |
| 5 | **장보기 리스트 연동 없음** — store에 shoppingList가 있지만 PricePage에서 "장바구니에 추가" 버튼이 없음 | `appStore.js` L62–L80 vs `PricePage.jsx` | 높 |
| 6 | **가격 알림 설정 UI 없음** — store에 priceAlerts가 있지만 "목표 가격에 도달하면 알림" 버튼이 없음 | `appStore.js` L83–L92 vs `PricePage.jsx` | 중 |

**개선 제안:**
- 상품 목록에 카테고리 탭 (채소류/축산물/과일류/가공식품) 추가
- 가격 등급 바 색상을 초록(좋은) → 노랑(보통) → 빨강(비쌈) 순서로 변경
- 상품 상세에 "장보기 리스트에 추가" 버튼 추가
- "이 가격 이하면 알림" 버튼 추가

### 4. 마트 할인 페이지 (MartPage)

**현재 상태:** 이마트/홈플러스/롯데마트/코스트코 탭 + 3개 모드(세일 상품/전단지/마트별 비교).

**좋은 점:**
- **3개 모드 토글** (세일 상품/전단지/마트별 비교)이 사용 시나리오별로 잘 분리됨 (`MartPage.jsx` L69–L79)
- **마트별 가격 비교** 모드에서 동일 상품의 마트별 가격을 나란히 표시 + 🏆 최저가 표시 (`MartPage.jsx` L164–L179)
- **행사 기간 표시**로 세일 유효기간 확인 가능 (`MartPage.jsx` L63–L66)
- **"DB 평균 대비" 비교**로 실제 할인인지 눈속임인지 판별 가능 (`MartPage.jsx` L137, L146–L149)
- 전단지 뷰어에 줌 인/아웃 기능

**문제점:**

| # | 문제 | 위치 | 심각도 |
|---|------|------|--------|
| 1 | **전단지 이미지가 placeholder** — 실제 전단지 이미지가 아닌 placehold.co 이미지. 전단지 뷰어의 가치가 0 | `mockData.js`의 flyerImg + `MartPage.jsx` L85–L89 | 높 |

| 3 | **세일 상품 카드에 클릭 이벤트가 navigate('/mart')** — 같은 페이지로 이동하므로 아무 일도 안 일어남. 상세 모달이 없음 | `MartPage.jsx` L138, L264 | 높 |
| 4 | **카테고리 필터가 이벤트 타입(1+1, 2+1 등)으로 분류** — 사용자가 원하는 것은 "신선식품/가공식품/생활용품" 같은 상품 카테고리 분류 | `MartPage.jsx` L6–L9 | 중 |
| 5 | **장보기 리스트 연동 없음** — "이 세일 상품을 장보기 리스트에 추가" 기능이 없음 | 전체 | 높 |
| 6 | **비교 모드에서 상품이 적을 수 있음** — commonProducts가 0개이면 빈 메시지만 표시. 비교 가치가 불확실 | `MartPage.jsx` L187–L190 | 낮 |

**개선 제안:**
- 세일 카드 클릭 시 상세 모달 표시 (마트 정보, 유사 상품 가격 비교, 장보기 추가 버튼)
- 카테고리 필터를 "상품 종류"와 "이벤트 타입" 두 가지로 분리
- 각 세일 카드에 "장보기에 추가" 버튼

### 5. 동네 물가 페이지 (LocalPage)

**현재 상태:** 좌측 지도(placeholder) + 우측 사이드바(주유소/식당 토글). 주유소: 유종별 가격 비교, 셀프 필터. 식당: 카테고리별, 시세 대비 가격.

**좋은 점:**
- **외식 vs 직접 조리 비교** 배너가 자취생(최수아)에게 실질적 가치 제공 (`LocalPage.jsx` L167–L183)

## 크리티컬 개선사항 (P0 — 반드시 수정)

### P0-1. 라이트 모드를 기본값으로 변경 + 테마 토글 추가
- **이유:** 타겟 사용자(한국 주부, 직장인)가 다크 모드 쇼핑 사이트에 익숙하지 않음. 네이버, 쿠팡, 당근마켓 모두 라이트 모드가 기본. 이탈률에 직결되는 문제.
- **현상:** `tokens.css`에 라이트 모드 토큰이 정의되어 있으나(`[data-theme="light"]`), 전환 UI 없고 기본값이 다크.

### P0-2. 하단 네비게이션에 '동네물가' 추가
- **이유:** 주유소 가격은 자주 확인하는 핵심 기능인데 모바일에서 접근이 어려움. 하단 네비게이션이 모바일의 주요 네비게이션인데 여기서 빠져 있으면 기능이 없는 것과 같음.
- **현상:** `BottomNav.jsx`에 5개 탭(홈/물가비교/핫딜/마트/더보기)만 있고, '더보기'가 커뮤니티로 직행. 주유소/식당 페이지로의 진입점 없음.

### P0-3. 홈페이지 카드 클릭 시 상세로 직접 이동
- **이유:** 홈의 핫딜/커뮤니티 카드를 클릭하면 전체 목록 페이지로만 이동하여, 사용자가 관심 있는 특정 아이템을 다시 찾아야 함. 클릭 기대와 결과의 불일치.
- **현상:** `HomePage.jsx` L188 (`navigate('/hotdeal')`), L311 (`navigate('/community')`)

### P0-4. 헤더 검색바 기능 연결
- **이유:** `Header.jsx` L98–L112의 검색 바가 UI만 있고 검색 로직이 없음. 사용자가 검색어를 입력해도 아무 결과가 나오지 않음. 전역 검색의 핵심 진입점.
- **현상:** `<input type="search" ... />` 이벤트 핸들러가 없고, 어떤 store나 router와도 연결되지 않음.

## 모바일 UX 체크리스트 (360px 기준)

| 항목 | 상태 | 비고 |
|------|------|------|
| 터치 타겟 44px 이상 | ✅ 대부분 준수 | `min-height: 44px` 적용됨 |
| 하단 네비게이션 | ⚠️ 동네물가 누락 | 5탭 중 1개가 잘못된 페이지로 연결 |
| 검색 입력 | ✅ 양호 | 포커스 시 키보드 올라와도 UI 깨지지 않음 |
| 가격 카드 그리드 | ✅ 2열→1열 | 480px 이하에서 적절히 축소 |
| 핫딜 카드 | ✅ 1열 | 768px 이하에서 1열 |
| 모달 | ⚠️ 닫기 어려움 | 스와이프 다운으로 닫기 미지원 |
| 마트 탭 | ⚠️ 가로 스크롤 없음 | 4개 탭이 flex-wrap으로 줄바꿈 — 2줄이 될 수 있음 |
| 지도 placeholder | ❌ 250px 공간 낭비 | 의미 없는 영역이 화면의 40% 차지 |
| 글쓰기 폼 | ✅ 1열 변환 | 600px 이하에서 1열로 적절히 변환 |
| 하단 여백 | ✅ | `padding-bottom: 100px` 으로 하단 네비 가려짐 방지 |
