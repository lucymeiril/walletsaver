- 역할: Sol low 한 명은 번호 묶음의 분류 제안, 주 에이전트는 분류 체계·예외·반영 책임. Gemini 추가는 비교 시험을 결정하기 전까지 보류한다.
- 입력: 현재 인증본에서 prepare로 만든 해시 고정 JSON과 필요한 리프 목록만. 전체 대화·DB·과거 보고서를 넘기지 않는다.
- 권한: 입력 읽기와 지정된 review-proposals JSON 하나의 신규 생성만. SQLite, 운영 폴더, Git, 네트워크, 추가 에이전트, 그 외 파일 변경, 테스트/빌드 실행 금지. 이는 지시 범위이지 OS 격리가 아니다.
- 출력: 번호→리프 그룹, 보류 이유, 별도 수량/할인 위험 번호. 긴 상품명이나 원본 필드 재작성 금지. 기존 리프 목록이 없으면 개념 제안만 하며 ID를 만들지 않는다.
- 분류 근거: 선반명보다 실제 상품 형태. 분류 가능 여부와 수량/가격 해결 여부를 구분한다. 수량 1 추정이나 혼합 구성 강제 분류 금지.
- 주 에이전트 검토: 번호 누락/중복·입력 해시·유효 리프는 기계 검사, 새 리프/혼합/충돌은 직접 검토. 같은 판단 유형은 묶어서 확인하며 전 상품을 다시 설명하지 않는다. 최초 시험은 전체 제안을 확인해 오류 유형을 파악한다.
- 검증: 제안만 받은 단계에는 DB 재생성하지 않는다. 반영 가능한 묶음을 모아 기존 decide와 하네스를 한 번 실행한다. 새로운 위험 유형이 있을 때만 의미 검사를 추가한다.
- 평가: 제안 수가 아니라 실제 채택·수정·보류·적재 수와 감독 부담을 구분해 기록한다. 요금/토큰 절감은 계측 없이는 주장하지 않는다.
- 반영 전용 에이전트는 추가하지 않는다. 분류 에이전트가 compact proposal 파일을 쓰고 경로/해시만 반환한다. 부모는 `catalog_review.py proposal` dry-run 요약을 검토한 뒤 `--apply`한다. 원문/긴 JSON/번호 명령을 부모가 재작성하지 않는다.
