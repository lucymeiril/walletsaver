Generated: 2026-05-18

## 구현 요약

### 백엔드 API
- `GET /api/match-monitor/cumulative` — ProductMatch 누적 수 (status/source별), LearnedKnowledge 누적 수 (type별, success_count 분포)
- `GET /api/match-monitor/runs?n=20` — 최근 N개 라벨링 런 (ai_call_rate 포함)

### 데이터 모델
- `LabelingRunLog` 신규 테이블 (ai_control.db)  
  - run_id, run_at, mode, ai_provider_kind
  - total_input, queue_initial, ai_called, ai_resolved, ai_escalated
  - gate_passed, gate_escalated, canonical_created
  - product_match_total_snapshot, learned_knowledge_total_snapshot, by_mart

### 파이프라인 훅
- `services/livepass_pipeline.py` — `emit_run_to_control_db(report, control_session)` 함수 추가  
  - `run_livepass()` 호출 후 control DB에 run stats 저장

### 프론트엔드 (`MatchMonitorPanel.jsx`)
- 4개 카드: ProductMatch 누적 / LearnedKnowledge 누적 / 최근 AI 호출률 / 총 런 횟수
- AI 호출률 추이 bar chart (순수 HTML/CSS)
- 최근 런 테이블 (일시, 모드, 입력, 큐진입, AI해결, Escalated, 게이트통과, AI호출률%, PM누적, LK누적)
- 빈 상태 처리: 런 없음 메시지 표시, 숫자 0으로 표시
