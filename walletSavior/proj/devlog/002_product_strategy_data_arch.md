# 개발일지 #2 — 제품 전략 + 데이터 아키텍처 설계

**날짜**: 2026-03-25  
**작업자**: AI + 사용자  
**유형**: 브레인스토밍 → 전략 정리

---

## 배경

React 마이그레이션을 끝내고 실제 프론트를 보니, 당장의 큰 문제가 보였다:
- **사진이 없다** — 핫딜 서비스에서 사진 없이는 신뢰감 제로
- **카테고리 깊이가 얕다** — "삼겹살"이 전부? 냉동/냉장/수입/국산/등급별로 나뉘어야 진짜 비교가 가능
- **통계의 신뢰도** — "싸다/비싸다"를 우리가 판단하는 건데, 그 기준이 얼마나 단단한가?

사용자와 브레인스토밍 후 정리한 핵심 과제와 아이디어:

---

## 1. 이미지 전략 — "사진 없는 핫딜은 핫딜이 아니다"

### 문제
현재 마트 전단, 핫딜 글, 가격 비교 어디에도 이미지가 없다. 핫딜 서비스의 핵심인데.

### 해결 방향

| 이미지 종류 | 출처 | 처리 방식 |
|---|---|---|
| **마트 전단 통 이미지** | 마트 웹사이트 크롤링 | 전단 전체를 저장 + 표시 |
| **전단 품목별 크롭** | 마트 전단에서 해당 상품 영역을 자르기 | 이미지 처리 (OpenCV or 수동 좌표) |
| **핫딜 썸네일** | 핫딜 게시판 크롤링 시 대표 이미지 수집 | 원본 URL 저장 또는 프록시 |
| **커뮤니티 업로드 사진** | 유저가 직접 올림 | S3/MinIO 업로드 + WebP 변환 + 썸네일 |
| **상품 대표 이미지** | 쿠팡/네이버쇼핑 등 | 크롤링 or 공식 API |

### 기술적 고려
- **CDN 분리**: 이미지는 DB에 URL만, 실파일은 CDN (S3 + CloudFront 또는 MinIO)
- **WebP 변환**: 업로드 시 자동 변환 (70% 용량 절감)
- **썸네일 자동 생성**: 원본 + 300px 2벌 저장
- **Lazy Loading**: 프론트에서 IntersectionObserver로 뷰포트 진입 시만 로드
- **전단 크롭**: 진짜 어려운 문제. 우선은 전단 통 이미지 보여주고, 나중에 OCR + 객체 검출로 자동화 고려

## 2. 카테고리 · DB 설계 — "양파가 다 같은 양파가 아니다"

### 문제
"삼겹살 100g 1,100원" → 이게 비싼 건가? 대답하려면:
- 냉동? 냉장? 생물?
- 국산? 수입산? 수입이면 스페인? 독일?
- 등급? 1등급? 1+등급?
- 동물복지? 무항생제?
- 마트 자체 브랜드(PB)? 정육코너? 온라인?

**같은 "삼겹살"이라도 속성에 따라 가격이 2~5배 차이**. 단순한 product_name 비교로는 의미 없음.

### 제안: 계층 + 태그 하이브리드

```
상품 카테고리 트리:
축산물
├── 돼지고기
│   ├── 삼겹살
│   ├── 앞다리
│   ├── 목살
│   └── 갈비
├── 소고기
│   ├── 등심
│   └── 갈비살
└── 닭고기
    ├── 가슴살
    └── 통닭

+ 속성 태그:
  [보관: 냉동/냉장/실온]
  [원산지: 국산/미국/호주/스페인/...]
  [등급: 1++/1+/1/2/3]
  [인증: 동물복지/무항생제/유기농/HACCP]
  [유형: 마트PB/일반/프리미엄/대용량]
  [단위: 100g/kg/팩/묶음]
```

### DB 테이블 설계 방향

```sql
-- 카테고리 트리
categories (id, parent_id, name, depth, path)
  예: (1, NULL, '축산물', 0, '축산물')
      (2, 1, '돼지고기', 1, '축산물>돼지고기')
      (3, 2, '삼겹살', 2, '축산물>돼지고기>삼겹살')

-- 상품 (실제 비교 단위)
products (id, category_id, name, standard_unit, standard_unit_amount)
  예: (1, 3, '삼겹살', '100g', 100)

-- 상품 속성 (유연한 태그)
product_attributes (product_id, attr_key, attr_value)
  예: (1, 'storage', '냉장')
      (1, 'origin', '국산')
      (1, 'grade', '1등급')

-- 기준 가격 (오염 불가)
baseline_prices (id, product_id, source, price, recorded_date)
  source: 'KAMIS' | 'KOSIS'
  -- 정부 공식 데이터만

-- 마트 할인 이력
discount_history (id, product_id, store, original_price, sale_price,
                  discount_rate, event_name, start_date, end_date, flyer_image_url)

-- 핫딜 (별도 저장, 평균에 불포함)
hotdeal_posts (id, product_id, title, price, source_url, source_name,
               posted_at, image_url, verified, verification_score)

-- 커뮤니티 (유저 제보)
community_posts (id, user_id, product_id, title, body, price,
                 images[], verified, verification_result, created_at)
```

### 분류의 현실적 접근
- **Phase 1**: KAMIS 카테고리 기준으로 대분류/중분류/소분류 구축 (정부 분류 체계 활용)
- **Phase 2**: 마트 크롤링 시 상품명에서 속성 자동 추출 (정규식 + 패턴 매칭)
- **Phase 3**: 나중에 LLM 또는 NLP로 상품명 → 카테고리 자동 매핑 고려

## 3. "집에서 해먹으면 얼마?" — 요리 비용 계산기

### 아이디어
식당에서 짜장면 6,500원 vs 집에서 재료 사서 만들면?
→ 면 + 춘장 + 양파 + 돼지고기 + 호박 = 1인분 ~2,800원

### 구현 방향
- 레시피 DB (간단한 것부터: 짜장면, 김치찌개, 된장찌개 등)
- 레시피별 재료 목록 + 기준 용량
- 재료 가격은 우리 baseline_prices DB에서 실시간 조회
- **UI**: "6,500원 내고 먹기 vs 2,800원에 해먹기 → 3,700원 절약!" 

### 우선순위: 나중 (DB + 레시피 데이터 필요)

---

## 4. 통계의 신뢰도 — "싸다고 말하려면 근거가 있어야"

### 문제
"평균 대비 30% 저렴" → 이 평균이 언제부터 언제까지의 평균? 이상치 포함? 계절 효과 보정?

### 해결
- **baseline은 정부 데이터만** (KAMIS, KOSIS) → 바이럴/조작 불가
- **이동평균** 사용 (7일/30일/90일) — 단순 평균보다 트렌드 반영
- **이상치 제거**: IQR 방식으로 극단값 필터링
- **계절성 보정**: 농산물은 계절 영향 큼 → 전년 동기 대비도 표시
- **데이터 기간 명시**: "이 통계는 180일간 1,247건 기준" → 투명성
- **신뢰구간**: 평균 ± 표준편차 범위 표시로 "진짜 싼 건지" 확실히

## 5. 패션/의류 할인 탭 — 확장

### 방향
- 무신사, 에이블리, W컨셉, 지그재그 등 의류 할인 정보 크롤링
- 핫딜 카테고리에 "패션" 필터 이미 존재 → 데이터만 채우면 됨
- 의류는 식품과 기준가 비교 방식이 다름 → "역대 최저가" 위주
- 가격 추적: 같은 상품의 가격 이력 (다나와 방식)

### 우선순위: 중 (크롤러만 추가하면 프론트는 이미 준비됨)

---

## 6. 커뮤니티 생태계 — "유저가 데이터를 만든다"

### 핵심 흐름
```
유저가 핫딜 글 작성
  → 품목 DB 매칭 필수 (자동완성)
  → 입력 가격 vs DB 평균 자동 비교
  → 너무 싸면: "허위 가격 의심" 경고
  → 너무 비싸면: "바이럴 의심" 경고
  → 범위 내면: "✅ 검증됨 - 평균 대비 -23%" 뱃지 자동 부착
```

### 커뮤니티 데이터 → 새로운 통계
- 유저 제보 가격은 **별도 테이블** (community_prices) → baseline 오염 방지
- 충분히 쌓이면 "커뮤니티 기반 시세" 별도 통계 가능
- 신뢰도 시스템: 좋아요/검증 횟수 누적 → 유저 "신뢰도 점수"
- 인기 핫딜러 랭킹 → 커뮤니티 활성화 인센티브

### 바이럴 필터링 규칙
1. 가격이 baseline 평균의 20% 미만 → "허위 의심" (등록차단 or 관리자 검토)
2. 가격이 baseline 평균의 120% 이상 → "바이럴 의심" (경고 표시)
3. 같은 IP에서 같은 마트 상품 반복 등록 → "광고 의심"
4. 신규 가입 후 즉시 글 작성 → "신뢰도 낮음" 표시
