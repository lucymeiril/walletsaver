# DECISIONS.md — AI 자율 결정 로그

> **이 문서의 목적**: AI가 기획서에 명시되지 않은 판단을 내렸을 때 기록하는 곳.
> 사람은 이 문서를 리뷰하여 승인/오버라이드/수정할 수 있다.
> 
> **마지막 업데이트**: 2026-03-25

---

## 사용법

AI가 자율 결정을 내리면 아래 포맷으로 추가:

```markdown
### D-NNN: [결정 제목] (YYYY-MM-DD)

**상황**: 왜 결정이 필요했나
**결정**: 무엇을 어떻게 결정했나
**근거**: 왜 이 선택이 최선인가
**대안**: 고려했지만 선택하지 않은 옵션
**리스크**: 이 결정의 잠재적 위험
**되돌림**: 사람이 반대하면 어떻게 원복하나
**상태**: `적용됨` | `사람 리뷰 대기` | `승인됨` | `오버라이드됨`
```

### 상태 플로우

```
AI 결정 → [적용됨] 또는 [사람 리뷰 대기]
                    ↓
          사람 리뷰 → [승인됨] 또는 [오버라이드됨]
```

- **적용됨**: AI가 판단하고 바로 코드에 반영 (저위험 결정)
- **사람 리뷰 대기**: AI가 판단했지만 코드 반영은 사람 승인 후 (고위험 결정)
- **승인됨**: 사람이 리뷰하고 OK
- **오버라이드됨**: 사람이 다른 방향으로 결정 → AI는 그에 따라 수정

## 결정 이력

### D-001: 문서 체계 5종 신규 생성 (2026-03-25)

**상황**: AI가 프로젝트 작업 시 세션 간 맥락 유지, 자율 판단, Git 관리를 체계적으로 하기 위한 문서가 부족
**결정**: AI_GUIDE.md, ARCHITECTURE.md, INVARIANTS.md, GLOSSARY.md, STATUS.md 5종 생성
**근거**: 기존 TECH_SPEC, DEV_PHILOSOPHY, ERROR_LOG만으로는 AI가 자율적으로 작업하기에 가이드 부족. 특히 아키텍처 시각화, 불변 제약 명시, 도메인 용어, 현황판이 없었음
**대안**: 기존 문서에 섹션 추가하는 방식 → 문서가 너무 비대해짐, 역할 불명확
**리스크**: 문서가 많아지면 업데이트 부담 증가
**되돌림**: 각 .md 파일 삭제만 하면 원복
**상태**: `승인됨` — 사용자 요청으로 생성

### D-002: AI 자율 판단 프로토콜 & 세션 핸드오프 시스템 도입 (2026-03-25)

**상황**: AI 세션이 끊어질 때 맥락이 소실되고, 미완성 기획을 AI가 채워가야 하는 요구사항
**결정**: AI_GUIDE.md에 문서 생명주기 프로토콜, 세션 핸드오프 포맷, Git 워크플로우, 자율 판단 가이드라인 추가. DECISIONS.md 신규 생성
**근거**: 사용자가 명시적으로 "인간 개입 없이 AI가 알아서 개발하면서 기획도 채워가야 한다"고 요구
**대안**: 사람이 매번 지시하는 방식 → 사용자 의도에 맞지 않음
**리스크**: AI 자율 결정이 사용자 의도와 다를 수 있음 → DECISIONS.md로 추적 + 사람 리뷰로 방어
**되돌림**: AI_GUIDE.md에서 Section 6~9 제거, DECISIONS.md 삭제
**상태**: `승인됨` — 사용자 요청으로 도입
