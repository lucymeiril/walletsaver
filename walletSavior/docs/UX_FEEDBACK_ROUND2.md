# 🔍 UX 피드백 2차 — 사용자 관점 평가

## 평가 일시: 2026-03-31

---

## 1. 총평

**점수: 6.5 / 10**

WalletSavior는 기획 의도가 명확하고, 한국 시장에 꼭 필요한 서비스다. "이 가격, 진짜 싼 건가요?"라는 히어로 카피는 즉각적으로 서비스 가치를 전달한다. 물가 비교, 마트 전단, 주유소, 커뮤니티까지 생활 물가 전반을 커버하려는 야심찬 구조가 잘 잡혀 있다.

하지만 현재 **MVP로서 실사용이 불가능한 수준**이다. 모든 데이터가 하드코딩된 Mock이고, 지도 API 미연동, 알림 기능 미구현, 커뮤니티 글쓰기 데모 수준, 로그인은 DOM 조작 기반이다. 당근마켓·네이버쇼핑·뽐뿌를 쓰는 한국 사용자의 눈높이에서 보면 "예쁜 목업"에 가깝다.

**잘 된 점:**
- 히어로 섹션의 가치 전달이 명확
- 가격 등급 시각화 (Tier Bar)가 직관적
- 장보기 리스트 FAB + 슬라이드 패널이 자연스러움
- 마트별 비교 뷰 (Compare) 기획이 우수
- 다크모드, 즐겨찾기, 최근 검색 등 persist 상태 설계가 좋음
- 핫딜 투표(🔥/❄️) 시스템이 뽐뿌 스타일로 친숙

**문제점:**
- 전체 데이터가 Mock → 실제 가치 제공 불가
- 모바일 내비게이션에 커뮤니티 탭 누락
- 가격 색상 코딩이 직관에 반함 (빨간색=역대급?)
- 알림/알럿 UI 미구현 (상태만 존재)
- 지도 API 미연동으로 동네물가 페이지 핵심 가치 없음

## 2. P0 — 즉시 수정 필요 (사용 불가)

### P0-1. 🚨 BottomNav에 커뮤니티 탭 누락

**현상:** 모바일 하단 내비게이션에 홈, 물가비교, 핫딜, 마트, 동네 5개만 있고 **커뮤니티가 없다.** 모바일 사용자는 커뮤니티 페이지에 접근할 방법이 없다 (헤더 nav는 768px 이하에서 숨김).

**위치:** `components/layout/BottomNav.jsx` — TABS 배열에 `/community` 경로 미포함

**수정안:** 5개 → 6개 탭으로 확장하거나, 마트/동네를 병합하여 커뮤니티를 추가. 또는 "더보기" 탭 추가.

---

### P0-2. 🚨 가격 등급 색상 체계가 직관에 반함

**현상:** HomePage의 핫딜 배지에서:
- `.ultra` → 빨간 배경 (`rgba(248,113,113,.12)`) → **빨간색이 "역대급 좋은 거"를 의미**
- `.good` → 초록 배경 → 초록이 "괜찮은 수준"
- `.ok` → 노란 배경 → 노란이 "보통"

이것은 한국 사용자의 상식과 정반대다. **빨간색 = 위험/비쌈/나쁨**, **초록 = 좋음/저렴** 이 보편적이다. 네이버쇼핑, 쿠팡 등 모든 한국 쇼핑 서비스가 이 규칙을 따른다.

그런데 `tokens.css`의 `--tier-ultra`는 초록(`#22c55e`), `--tier-wait`는 빨강(`#f87171`)으로 올바르게 정의되어 있다. **토큰은 맞지만 실제 컴포넌트에서 잘못 적용**하고 있다.

**위치:**
- `HomePage.module.css` L298-301: `.ultra`, `.great`, `.good`, `.ok` 클래스
- `HotdealPage.module.css` L126-129: 동일 문제
- `HotdealPage.jsx` L16-19: `getTier` 함수의 color 매핑

**수정안:**
```
역대급(≤40%) → 초록 (#22c55e) — 강한 초록, 즉시 구매
대박(≤60%) → 파랑 (#38bdf8) — 좋은 가격
괜찮은(≤80%) → 노랑 (#fbbf24) — 보통
보통(>80%) → 빨강/회색 (#f87171) — 기다려
```

---

### P0-3. 🚨 로그인 구현이 React 안티패턴

**현상:** `Header.jsx` L42-44:
```js
const openLogin = () => {
  document.getElementById('modal-login')?.classList.add('open');
};
```
React에서 직접 DOM을 조작하는 것은 안티패턴이다. 상태가 동기화되지 않아 모달이 열렸는데 React는 모르는 상태가 된다.

**수정안:** Zustand 스토어에 `isLoginModalOpen` 상태를 추가하고, LoginModal 컴포넌트에서 이를 구독하도록 변경.

---

### P0-4. 🚨 커뮤니티 댓글/투표가 새로고침 시 소실

**현상:** 핫딜 투표(`votes` state), 커뮤니티 댓글(`comments` state)이 모두 컴포넌트 로컬 상태다. 페이지를 벗어나거나 새로고침하면 모든 사용자 인터랙션이 사라진다.

**수정안:** 최소한 Zustand persist로 저장하고, 장기적으로는 백엔드 API 연동.

---

### P0-5. 🚨 LocalPage 지도 미연동 → 핵심 가치 부재

**현상:** "우리 동네 물가 지도"인데 지도가 플레이스홀더다. 주유소 거리도 `0.5 + i * 0.3`으로 가짜 계산. "가까운 주유소"라는 서비스 약속을 전혀 이행하지 못함.

**수정안:** Kakao Maps SDK 연동하거나, 최소한 주소 기반 거리 계산이라도 구현. 지도 없이도 현위치 기반 정렬은 가능 (Geolocation API).

## 3. P1 — 중요 개선사항 (사용성에 큰 영향)

### P1-1. 검색 자동완성이 Mock 데이터 ~8개 상품에만 동작

**현상:** PRODUCTS 배열에 있는 소수의 상품만 검색 가능. "삼겹살"은 되지만 "돼지고기 앞다리" 같은 변형은 불가. 사용자가 2-3번 검색해서 결과가 없으면 바로 이탈한다.

**수정안:** 최소 100개 이상의 주요 품목 데이터 확보. 초성 검색(`ㅅㄱㅅ` → 삼겹살), 유사어 매칭 필요.

---

### P1-2. 알림 벨 아이콘이 아무 기능도 없음

**현상:** Header에 Bell 아이콘이 있고, `notifications` 상태를 참조하지만, 클릭해도 아무 일도 안 일어남. `priceAlerts` 상태도 스토어에 정의만 되어 있고 UI가 없음.

사용자 기대: "양파 3,000원 이하 되면 알려줘" → 이 기능이 안 된다.

**수정안:** 알림 드롭다운 패널 + 가격 알림 설정 UI (PricePage 상세에서 "목표 가격 설정" 버튼 추가).

---

### P1-3. 장보기 리스트에 수량 조절 UI 없음

**현상:** 장보기에 추가하면 수량이 1로 시작되고, 같은 상품을 다시 추가하면 +1 된다. 하지만 패널에서 **수량을 줄이거나 직접 변경하는 UI가 없다.** 삭제만 가능.

**수정안:** 수량 `–` / `+` 버튼 추가. 수량 0이 되면 자동 삭제.

---

### P1-4. PricePage 상품 미선택 시 UX가 약함

**현상:** `/price`로 직접 진입하면 전체 상품 그리드가 표시되는데, "여기서 뭘 해야 하는지" 안내가 부족. 검색 입력창의 placeholder만으로는 서비스를 이해하기 어려움.

**수정안:**
- "🔍 확인하고 싶은 상품을 선택하세요" 같은 안내 문구 추가
- 인기 검색 상품 상위 3개를 featured card로 표시
- 상품 카드에 "지금 싼가요?" 같은 액션 문구 추가

---

### P1-5. 마트 전단지 뷰어의 이미지가 Mock

**현상:** `flyerImg`가 Mock 데이터에서 오는데, 실제 전단지 이미지가 없을 가능성 높음. 이미지 로드 실패 시 대체(fallback) UI가 없다.

**수정안:** `<img>` 태그에 `onError` 핸들러 추가, 기본 이미지 또는 "전단지 준비 중" 메시지 표시.

---

### P1-6. 핫딜 상세 모달에서 원본 링크 접근이 어려움

**현상:** `item.url`이 있을 때만 "🔗 원본 보기" 링크가 보이는데, 핫딜의 핵심은 **원본 구매 페이지로 이동**하는 것. Mock 데이터에 url이 없으면 사용자가 어떻게 구매하는지 모름.

**수정안:** 구매 링크를 필수 필드로 만들고, 모달 하단에 고정된 CTA 버튼("🛒 구매하러 가기")으로 노출.

---

### P1-7. 헤더 검색 → 물가비교 페이지 연동 불완전

**현상:** Header의 `handleSearch`가 `/price`로 네비게이트하면서 `state: { searchQuery }`를 전달하지만, PricePage에서 `location.state.searchQuery`를 읽는 코드가 없다. 검색해도 결과가 안 보임.

**수정안:** PricePage의 `useEffect`에서 `location.state?.searchQuery`를 받아서 `setSearchQuery`로 반영.

---

### P1-8. 모바일에서 홈페이지 검색 드롭다운이 화면을 가림

**현상:** 자동완성/인기검색어 드롭다운의 `max-height: 340px`이 모바일 화면 대부분을 차지. `box-shadow: rgba(0,0,0,.4)`도 모바일에서는 너무 강함.

**수정안:** 모바일에서는 전체 화면 검색 오버레이로 전환 (당근마켓 스타일).

## 4. P2 — 개선 제안 (있으면 좋은 것)

### P2-1. 스켈레톤 로딩 미적용

Suspense fallback이 단순 spinner인데, 카드/리스트 형태의 스켈레톤 UI가 훨씬 자연스럽다. 특히 HomePage의 여러 섹션이 한번에 뜨면서 레이아웃 쉬프트가 발생할 수 있음.

---

### P2-2. BottomNav 배경색이 테마 무관하게 항상 어두움

`BottomNav.module.css` L5: `background:rgba(11,15,25,.88)` — 라이트 모드에서도 검은 바텀 네비는 iOS/안드로이드 네이티브 앱과 이질감이 있다.

**수정안:** `var(--surface)`와 `backdrop-filter` 조합으로 테마에 맞는 반투명 배경 적용.

---

### P2-3. 즐겨찾기 목록을 볼 수 있는 페이지가 없음

`favorites` 상태가 persist되지만, 즐겨찾기한 상품 목록을 모아보는 화면이 없다. 사용자가 ❤️를 눌러도 다시 찾을 방법이 없음.

**수정안:** 마이페이지 또는 PricePage에 "내 관심 품목" 필터 추가.

---

### P2-4. 커뮤니티 자유게시판 데이터가 컴포넌트 내 하드코딩

`FREE_POSTS_MOCK`이 CommunityPage 컴포넌트 파일 안에 직접 정의됨. mockData 파일로 분리해야 유지보수와 테스트가 용이.

---

### P2-5. 물가비교 차트에 평균가 기준선 없음

가격 추이 AreaChart에 평균가를 나타내는 수평 점선이 없다. 사용자가 "지금 가격이 평균 대비 어떤지"를 차트에서 직관적으로 파악 불가.

**수정안:** `ReferenceLine` 컴포넌트로 평균가 표시, "평균" 라벨 추가.

---

### P2-6. 접근성(a11y) 미흡

- 검색 드롭다운에 `role="listbox"`, `aria-activedescendant` 없음
- 모달에 포커스 트랩 없음 (Tab키로 모달 뒤 요소에 포커스 이동)
- 이미지에 의미있는 `alt` 텍스트 부재 (`alt=""`)
- 색상 대비: `--text3: #94a3b8`이 `--bg: #f8fafc` 위에서 WCAG AA 미달 가능

---

### P2-7. 에러 처리/경계 없음

React ErrorBoundary가 보이지 않음. 차트 라이브러리나 이미지 로드 실패 시 전체 페이지가 크래시할 수 있음.

---

### P2-8. 외식 vs 직접조리 비교가 짜장면 하나뿐

LocalPage의 "Cook vs Eat" 배너가 `RECIPES.find(r => r.name === '짜장면')`으로 하드코딩. 다양한 메뉴 비교를 동적으로 보여줘야 함.

---

### P2-9. 마트 세일 상품 이미지 없음

마트 할인 카드에 상품 이미지가 없어 시각적 매력이 떨어진다. 쿠팡/마켓컬리 수준의 상품 사진이 있으면 전환율이 크게 오를 것.

---

## 5. 추가 기능 제안

### 🔔 가격 알림 (Price Alert)
**우선순위: ★★★★★**

스토어에 `priceAlerts` 상태가 이미 정의되어 있으나 UI가 없다. PricePage 상세에서 "목표 가격 설정" 버튼 → 슬라이더로 알림 가격 설정 → 웹 푸시 또는 카카오톡 알림. 이것이 **매일 재방문하게 만드는 핵심 기능**.

### 📊 주간 물가 리포트
매주 월요일 "지난 주 이렇게 변했어요" 요약 제공. 즐겨찾기 품목 기준으로 개인화된 리포트.

### 📱 카카오톡 공유
핫딜/물가 정보를 카카오톡으로 공유. `--kakao` 색상 토큰이 이미 정의되어 있으므로 Kakao SDK 연동만 하면 됨. 바이럴 성장의 핵심.

### 🏷️ 바코드/상품명 스캔
마트에서 직접 상품 바코드를 스캔하면 → 현재 가격 등급 표시 + 다른 마트 가격 비교. "지금 이걸 사는 게 맞나?" 즉석 판단 도구.

### 📍 마트별 최적 장보기 경로
장보기 리스트를 만들면 → "이마트에서 3개, 롯데마트에서 2개 사면 총 15,000원 절약" 같은 최적화 추천.

### 👤 사용자 프로필 & 등급
커뮤니티 기여도(핫딜 공유, 댓글, 투표)에 따른 등급. 뽐뿌의 레벨 시스템 참고. 신뢰도 높은 사용자의 핫딜이 상위 노출.

### 📈 장보기 히스토리 & 절약 대시보드
"이번 달 장보기에 15만원 씀 / 평균 대비 2.3만원 절약" 같은 통계. 절약 게이미피케이션.

### 🔄 실시간 품절/재고 정보
커뮤니티 크라우드소싱으로 "코스트코 하남점 삼겹살 품절" 같은 실시간 재고 정보.

## 6. 페이지별 상세 피드백

---

### HomePage

**잘 된 점:**
- 히어로 카피 "이 가격, 진짜 싼 건가요?"가 서비스 본질을 정확히 전달
- 카테고리 퀵링크 6개 → 3클릭 내 목표 접근 가능
- 오늘의 물가 카드에 트렌드 아이콘(↑↓→)이 직관적
- 마트별 탭 전환이 부드러움
- 장보기 추가 🛒 버튼이 각 카드에 자연스럽게 배치됨

**문제점:**
- **정보 과밀:** 한 페이지에 히어로 + 카테고리 + 핫딜 + 물가 + 마트 + 주유소 + 커뮤니티 = 7개 섹션. 스크롤이 끝이 없음. 당근마켓은 메인에 1-2개 섹션만 보여줌.
- **카테고리 "식당"이 Local, "배달"이 Community로 연결됨** → 기대와 다른 목적지. 배달 카테고리 → 커뮤니티? 직관적이지 않음.
- **최근 검색 칩이 히어로 하단에 또 표시됨** (L139-151) → 검색 드롭다운 안에도 있어서 중복. 시각적 혼란.
- **`quickTags`와 `TRENDING`이 중복 데이터** — 삼겹살, 계란, 양파 등이 양쪽에 다 있음.
- 물가 카드 `.priceCard` 호버 그림자가 `rgba(0,0,0,.3)`으로 너무 강함. 라이트 모드에서 부자연스러움.

**모바일:**
- 카테고리 3열 그리드가 적절
- `min-height: 44px`으로 탭 타겟 준수 ✅
- 하단 패딩이 BottomNav(60px)를 고려하지 않는 섹션 있음

### HotdealPage

**잘 된 점:**
- 필터(카테고리) + 소스(출처) + 정렬 3단 컨트롤이 잘 구성됨
- 무한 스크롤(`useInfiniteScroll`) 구현 ✅
- 카드에 시세 대비 배지(`dbBadge`)가 있어 실질적 정보 제공
- 🔥/❄️ 투표 시스템이 카드 레벨에서 바로 가능
- 상세 모달에 가격 추이 차트 내장 — 핫딜 페이지에서 바로 시세 확인 가능

**문제점:**
- **배지가 너무 많아 정보 과밀:** 한 카드에 tier 배지 + 할인% 배지 + 시세 대비 배지 = 최대 3개. 핵심 정보 1개로 통합 필요.
- **투표 수가 카드에 `🔥 0 / ❄️ 0`으로 표시** → 모든 딜이 0표라서 신뢰감 없음. Mock에서라도 초기값 넣어야 함.
- **소스 필터 버튼이 너무 많음** (6개) → 480px 이하에서 2줄로 내려감. 가로 스크롤 또는 드롭다운으로 변경 추천.
- 상세 모달의 댓글이 모달 닫으면 유실됨 (컴포넌트 로컬 state).
- 썸네일 이미지(`d.thumb`)가 없는 딜은 이미지 없이 텍스트만 보여 카드 높이가 불균일.

### PricePage

**잘 된 점:**
- **타이밍 배지** ("역대급 기회!", "좋은 가격이에요!", "조금 기다려보세요")가 매우 직관적이고 사용자 친화적
- **적정 핫딜가** 안내 (평균의 80%) → 구매 기준을 명확히 제시
- **가격 등급 바 (Tier Bar)** 시각화가 우수 — 현재 위치를 한눈에 파악
- 마트별 가격 바 차트가 유용
- 속성 변형 (국산/수입, 냉동/냉장) 선택이 세밀함
- **상세 분석 모드** 토글 — 일반/전문가 사용자 분리 좋음

**문제점:**
- **우측 사이드바가 모바일에서 메인 콘텐츠 아래로 이동** → 마트별 비교를 보려면 긴 스크롤 필요. 탭으로 전환하는 게 나음.
- **관련 핫딜이 `cat === 'food'`로 하드코딩** (L338) → 전자제품을 보고 있어도 food 핫딜만 보임.
- 검색 결과 없을 때 "검색 결과가 없습니다" 메시지가 없음 → 빈 그리드만 보임.
- 상품 목록 → 상세로 전환 시 애니메이션이 없어 갑작스러움.
- 차트 데이터 `genPriceHistory`가 랜덤 생성이라 새로고침마다 다른 차트가 보임 → 신뢰도 저하.

### MartPage

**잘 된 점:**
- 3가지 모드(세일 상품 / 전단지 / 마트별 비교) 전환이 깔끔
- 전단지 뷰어의 줌 인/아웃이 모바일에서 유용
- 카테고리(행사 유형) 필터가 실용적
- **마트별 비교 뷰가 킬러 기능** — 같은 상품의 마트간 가격을 한눈에 비교
- 상세 모달의 정보 레이아웃이 깔끔 (판매가/정가/할인율/기간/마트/행사유형)

**문제점:**
- **행사 기간이 텍스트로만 표시** → "~ 4/3" 같은 날짜가 지나도 여전히 표시. D-day 카운트다운이 있으면 긴급감 유발.
- 전단지 이미지가 Mock이라 실제로는 깨진 이미지가 보일 가능성.
- 비교 뷰에서 최저가 마트에 🏆만 있고, **"여기가 X원 더 싸요"** 같은 절약 금액 표시가 없음.
- `findCommonProducts` 함수의 상품명 정규화가 불안정 — "삼겹살 1kg"과 "국내산 삼겹살"을 같은 상품으로 인식 못할 수 있음.

### LocalPage

**잘 된 점:**
- 주유소/식당 탭 분리가 명확
- 유종(휘발유/경유/LPG) 전환 + 셀프 주유소 필터가 실용적
- 1~3등 순위 색상 차별화 (금/은/동)
- **외식 vs 직접 조리 비교 배너**가 독창적이고 실용적
- 상세 모달의 유종별 가격 + 운영 정보가 충실

**문제점:**
- **지도가 없다.** "우리 동네 물가 지도"인데 지도가 플레이스홀더. 이것은 페이지의 존재 이유를 부정함.
- **거리 계산이 가짜:** `(0.5 + i * 0.3).toFixed(1)km` — 리스트 순서에 따라 거리가 결정됨. 1등이 항상 0.5km, 2등이 0.8km...
- **길찾기 버튼이 `alert()` 호출** → 네이티브 alert는 절대 프로덕션에서 쓰면 안 됨.
- 식당 카테고리가 '한식', '중식', '카페' 3개뿐 → 일식, 양식, 분식, 패스트푸드 등 부족.
- `selfOnly` 체크박스 UI가 `✅`/`⬜` 이모지 기반 → 네이티브 체크박스 또는 커스텀 토글이 나음.

### CommunityPage

**잘 된 점:**
- 핫딜 게시판 / 자유 게시판 분리가 좋음
- **자동 시세 검증** (verifyPrice)이 킬러 기능 — 허위 가격 필터링
- 글쓰기 폼이 게시판 타입별로 다른 필드 표시 (핫딜: 품목/가격/링크, 자유: 태그)
- 이미지 업로드 프리뷰 + 삭제가 잘 됨
- 검색 + 정렬 + 카테고리 필터 3중 컨트롤이 유연

**문제점:**
- **글쓰기가 로그인 필수인데, 로그인 기능이 사실상 없음** → 사용자는 영원히 글을 쓸 수 없음.
- **핫딜 게시글의 좌측 컬러 보더** (`border-left: 4px`) 색상이 검증 상태에 따라 변하지만, 색상 범례(legend)가 없어 의미를 모름.
- 페이지네이션이 있는데 핫딜 페이지는 무한스크롤 → **일관성 없음.** 둘 중 하나로 통일해야.
- 자유 게시판의 Mock 데이터가 컴포넌트 내부에 있음 (550줄 파일의 L24-33) → 분리 필요.
- 게시글 본문 프리뷰가 `slice(0, 60)` + `...`으로 잘리는데, 한글은 60자면 너무 김. 2줄 clamp가 나음.

- 480px 이하에서 패널이 전체 화면(100vw) → 모바일에서 적절 ✅
